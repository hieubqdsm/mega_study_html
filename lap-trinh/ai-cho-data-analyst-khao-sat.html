Hướng dẫn chuẩn doanh nghiệp dành cho Data Analyst xử lý hàng nghìn cột × hàng trăm nghìn dòng. Bạn không cần giỏi code hay thao tác Git thuần thục — tài liệu này giúp bạn nhờ AI viết pipeline, giải thích code và bắt lỗi để làm chủ hoàn toàn quá trình xử lý.

Triết lý của phương pháp Không phải "đưa data và phó mặc cho AI". Cách đúng đắn: Nhờ AI viết → Yêu cầu giải thích → Hiểu để bắt lỗi → Phản hồi chỉnh sửa. Bạn đóng vai trò là "Người điều phối" (Orchestrator), AI là "Lập trình viên thực thi".
Phần 1 · Nền tảng & File Setup

Chương 0 Sự thật: AI không hiểu data nếu thiếu context

Bài học quan trọng nhất: AI chỉ giỏi khi bạn cho đủ ngữ cảnh. Context là quá trình xây dựng qua tương tác, không phải 1 câu lệnh ăn liền.

Nếu bạn upload file data thô CSV vào ChatGPT và yêu cầu: "Kiểm tra respondent này có nói xạo không". AI sẽ thất bại. Tại sao? Vì nó chỉ thấy các mã hóa như profile-qbirthyear và không hề biết:

  • Cột này chứa định dạng gì? (năm, text, hay mã số quy ước?)
  • Thế nào được định nghĩa là "Nói xạo" trong nghiệp vụ của bạn?
Lỗi phổ biến #1 Tin rằng "AI tự hiểu mọi thứ". Thực tế: AI chỉ thấy các con số. Không có từ điển giải nghĩa, nó sẽ đoán mò (hallucinate) và đưa kết quả sai lệch.

Context không phải 1 câu — là một quy trình

Với bộ data lớn, quá trình bơm ngữ cảnh (context) phải được thực hiện theo từng bước:

  1. Đưa nền tảng: Cung cấp 3 file setup (questionnaire, structure, behavior) để AI giải mã các cột.
  2. Kiểm tra xác nhận: Yêu cầu AI tóm tắt lại để chắc chắn nó hiểu đúng loại dữ liệu.
  3. Bổ sung Rule/Nghiệp vụ: Đưa mô tả nghiệp vụ (VD: định nghĩa nói xạo) và bảng map dữ liệu (nếu có).
  4. Thực thi & Tinh chỉnh: Áp dụng vào xử lý dữ liệu và kiểm tra 5 dòng kết quả mẫu.

Chương 1 Môi trường & Giới hạn của Excel

Vì sao phương pháp cũ (Excel + Power Query) thất bại trước Big Data khảo sát, và giải pháp Python local.

Quy trình thủ công thường yêu cầu thêm 20-50 cột logic bằng công thức. Tuy nhiên, khi dữ liệu đạt ngưỡng 2000 cột × 200.000 dòng:

  • Excel / Power Query: Máy treo, crash do thiếu RAM, tốc độ tính toán từng dòng quá chậm.
  • Python (AI sinh code): Chạy trên cơ chế vector hóa (xử lý toàn bộ cột cùng lúc) nên hoàn thành trong vài giây.
Môi trường làm việc chuẩn Vì dữ liệu lớn, các nền tảng đám mây miễn phí (như Google Colab) sẽ dễ bị quá tải RAM hoặc đứt kết nối. Lựa chọn an toàn và tối ưu nhất là setup máy tính Local (Python 3.12+, VS Code, và thư viện Pandas). AI sẽ hướng dẫn bạn cài đặt từ con số không.

Chương 2 Nhận diện các file Context

Bạn không cần tự đọc từng dòng, nhưng bạn phải biết tác dụng của từng file để gọi tên khi giao việc cho AI.

Tên FileTác dụng đối với AI

Chương 3 Quy trình tương tác AI chuẩn mực

Giao tiếp với AI là quy trình qua lại (multi-turn). Đừng gộp tất cả yêu cầu vào một câu lệnh khổng lồ.

Kịch bản tương tác 4 bước

Bước 1: Mớm nền tảng

📋 Lượt 1 — Yêu cầu AI đọc cấu trúc Tương tác
Tôi là Data Analyst. Đính kèm 3 file setup (questionnaire, structure, behavior) và file data.csv của đợt khảo sát. Hãy đọc 3 file setup để hiểu cấu trúc. Mở data.csv, check 2 cột (profile-qbirthyear, profile-qyear-of-study) để xác nhận bạn đọc đúng cách. Tóm tắt ngắn gọn: Bạn hiểu quy ước lưu data thế nào?

Bước 2 & 3: Bổ sung Rule & Xử lý mẫu

📋 Lượt 2 — Áp dụng quy tắc (Rule) Tương tác
Bạn đã hiểu đúng cấu trúc. Hãy áp dụng rule kiểm tra sau: "Sinh viên sinh năm 2007 nhưng đang học năm 3 hoặc năm 4 → Đánh dấu là nói xạo". Hãy viết code Python tạo cột [rule_sayso_2007] (=1 nếu vi phạm). In ra 5 dòng ví dụ để tôi kiểm tra code của bạn có xử lý đúng logic không.

★ Lưu Context vào Markdown (Tài sản dự án)

Đừng để mất công giải thích lại từ đầu ở các phiên chat sau. Hãy biến AI thành thư ký ghi chép.
📋 Nhờ AI đóng gói kiến thức vào Markdown Bảo lưu ngữ cảnh
Bạn đã nắm toàn bộ cấu trúc data và bộ rule của khảo sát này. Hãy tổng hợp tất cả vào 2 file Markdown (.md): 1. context_q3.md: Tóm tắt cấu trúc bảng hỏi, cách đọc các loại cột (single/multiple/scale). 2. rules_q3.md: Danh sách nghiệp vụ và tên cột liên quan để xử lý phán quyết. Hãy viết thật chuẩn xác để ở phiên làm việc sau, tôi chỉ cần upload 2 file này là bạn có thể tiếp tục công việc ngay lập tức.
Phần 2 · Điều Khiển AI Xử Lý

Chương 4 Công cụ AI & Cảnh báo Bảo mật

Chọn đúng mô hình (Model) và Giao diện (Interface) giúp tăng tốc công việc, đồng thời đảm bảo tuân thủ tuyệt đối quy tắc bảo mật dữ liệu công ty.
🚨 CẢNH BÁO ĐỎ: BẢO MẬT DỮ LIỆU (DATA PRIVACY)

Việc sử dụng AI mang lại rủi ro rò rỉ dữ liệu (Data Breach) rất lớn nếu không cẩn thận. Bạn phải tuân thủ nghiêm ngặt nguyên tắc sau:

  • TUYỆT ĐỐI KHÔNG upload file data thô (Raw Data) có chứa thông tin cá nhân định danh (PII) như: Tên, Email, Số điện thoại, Địa chỉ, IP của respondent lên các công cụ AI công cộng (ChatGPT, Claude web, Gemini).
  • Cách làm đúng: Bạn chỉ upload 3 file cấu trúc (Setup files) + 1 bảng data giả lập (Mock data khoảng 100 dòng, đã xóa toàn bộ cột thông tin cá nhân) để nhờ AI viết code.
  • Sau khi AI viết xong file Python, bạn lấy code đó và chạy trực tiếp trên máy tính local của bạn (qua VS Code) với file dữ liệu thật. Bằng cách này, dữ liệu khách hàng không bao giờ rời khỏi máy tính công ty.

Chương 5 Giải mã file Data

Bước đầu tiên với mọi project khảo sát: Để AI bóc tách cấu trúc thành một bản đồ dễ nhìn.
📋 Khảo sát cấu trúc Khởi tạo
Bạn là Data Analyst. Dựa vào 3 file setup đính kèm (không có data thật), hãy vẽ ra "Bản đồ Dữ liệu": 1. Khảo sát này có bao nhiêu phần? 2. Có bao nhiêu câu hỏi dạng Multiple Choice, Scale, Single Choice? 3. Với câu hỏi trọng tâm (VD: Mức độ hài lòng), thang điểm là 1-5 hay 1-10? Liệt kê thành danh sách gạch đầu dòng rõ ràng.

Chương 6 Apply Rule Hàng Loạt (Batch Processing)

Thay vì thêm từng cột Excel, hãy đưa danh sách 30-50 quy tắc để AI tạo một Script xử lý tất cả trong một lần chạy.
📋 Tạo Script áp dụng 50 Rules Core Logic
Dựa trên file Mock Data và 3 file Setup đính kèm, tôi cần viết code Python (Pandas) áp dụng danh sách các quy tắc (Rule) sau đây. Mỗi Rule sẽ tạo ra 1 cột mới mang giá trị 1 (Vi phạm) hoặc 0 (Hợp lệ). [DANH SÁCH RULE] 1. rule_sayso_age: "Sinh viên sinh năm 2007 nhưng tự khai là năm 3 hoặc năm 4" (Cột: qbirthyear, qyear) 2. rule_speeding: "Thời gian hoàn thành khảo sát (submit_time - start_time) < 3 phút" 3. rule_straightlining: "Đánh cùng 1 mức điểm cho toàn bộ lưới câu hỏi EBA" ... [Tiếp tục liệt kê] [YÊU CẦU KỸ THUẬT] - Xử lý mượt mà các giá trị rỗng (NaN) bằng kỹ thuật Masking. - Tối ưu bộ nhớ (Memory Optimization): Sử dụng kỹ thuật chunksize hoặc optimize dtypes vì dữ liệu thật của tôi lên tới 200.000 dòng. - Viết code sạch, có comment tiếng Việt ở từng khối xử lý.

Chương 7 Phán Quyết Chất Lượng (Verdict)

Tổng hợp hàng chục cột vi phạm thành 1 nhãn cuối cùng: QUALIFIED, REVIEW, hoặc REJECT.

Phán quyết phụ thuộc vào nghiệp vụ từng công ty. Thường là sự kết hợp (Composite) giữa "Lỗi nghiêm trọng" (Hard Fail) và "Điểm tin cậy" (Score).

Chương 8 Thống Kê & Báo Cáo

AI không chỉ dọn data, nó còn có thể sinh file Excel báo cáo đẹp mắt để gửi sếp.
Luôn thêm yêu cầu: "Hãy tự động xuất bảng tỷ lệ loại bỏ (Reject Rate) theo từng Rule, và sinh ra 3 câu Insight (Nhận định) bằng tiếng Việt để tôi đưa thẳng vào báo cáo."

Chương 12 Commit Git An Toàn & Chuẩn Mực

Lưu trữ Pipeline code lên GitLab/GitHub. Bạn chưa thạo lệnh Git? AI sẽ hướng dẫn từng dòng lệnh.
🚨 LƯU Ý TỐI QUAN TRỌNG: TUYỆT ĐỐI KHÔNG COMMIT DATA NHẠY CẢM

File data thật chứa thông tin respondent là tài sản bảo mật. Việc gõ nhầm lệnh đẩy file CSV này lên GitHub/GitLab là sự cố an toàn thông tin (Security Incident) nghiêm trọng nhất.

  • Chỉ commit: Code Python (`run_report.py`), file cấu trúc (`context.md`, `README.md`), và file template rule (không chứa data).
  • Bắt buộc sử dụng `.gitignore`: Trước khi chạy lệnh Git đầu tiên, YÊU CẦU AI tạo ngay file `.gitignore` và liệt kê chặn tất cả các định dạng data (VD: `*.csv`, `*.xlsx`, thư mục `/data/`).
  • Nếu lỡ commit nhầm file data, KHÔNG CHỈ xóa file trên máy rồi commit lại (vì dữ liệu vẫn kẹt lại trong lịch sử Git). Hãy báo ngay cho IT Admin để tiến hành thanh trừng (purge) lịch sử repository.
📋 Prompt tạo lệnh Git an toàn Quản lý Version
Tôi là Data Analyst, chưa thạo Git. Tôi cần đẩy đoạn code Python và file cấu trúc (.md) vừa tạo lên repo GitLab công ty. Yêu cầu bắt buộc: 1. Tạo nội dung file `.gitignore` chuẩn để chặn toàn bộ mọi file CSV, Excel, và thư mục `/data_raw/` nhằm đảm bảo không rò rỉ dữ liệu. 2. Cung cấp tuần tự các dòng lệnh terminal để tôi init repo, add (sau khi đã có gitignore), commit (viết sẵn nội dung commit tiếng Việt), và push. 3. Giải thích ngắn gọn tác dụng của mỗi dòng lệnh để tôi có thể học hỏi.
