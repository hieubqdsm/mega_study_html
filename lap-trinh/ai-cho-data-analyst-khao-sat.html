Điều khiển AI xử lý dữ liệu khảo sát lớn

Hướng dẫn cho team Data Analyst xử lý khảo sát (data hàng nghìn cột × hàng trăm nghìn dòng). Bạn chưa biết code hay git cũng không sao — hãy nhờ AI viết trước, rồi nhờ AI giải thích từng bước để bạn hiểu và biết AI sai chỗ nào mà sửa. Qua vài vòng, bạn tự chủ làm chủ công nghệ. Mọi thao tác qua prompt tiếng Việt.

🤖 20+ prompt copy-paste
📝 3 file setup + rule template
⏱️ 4–6 tuần
🎯 Cách tiếp cận của hướng dẫn này Không phải "không cần học gì". Cách đúng: không cần biết ngay → nhờ AI viết trước → nhờ AI giải thích cái nó vừa viết để hiểu → đọc hiểu đủ để bắt lỗi AI và yêu cầu sửa. Học qua làm, chủ động, từng bước. AI là người viết code — bạn là người kiểm tra và định hướng.
P1 · Nền tảng & 3 File Setup

Chương 0 ★ Sự thật: AI không hiểu data nếu thiếu context

Bài học quan trọng nhất: AI chỉ giỏi khi bạn cho đủ ngữ cảnh. Và context không phải 1 câu "1 phát ăn ngay" — là quá trình xây dựng qua tương tác.

Hãy tưởng tượng bạn upload file data CSV vào ChatGPT rồi gõ: "Kiểm tra respondent này có nói xạo không". Kết quả? AI sẽ không làm được — vì nó chỉ thấy các con số và tên cột mã hóa (profile-qbirthyear...), không biết:

  • Cột đó chứa giá trị gì? (số năm? mã? text?)
  • "Nói xạo" được định nghĩa thế nào? Rule kiểm tra là gì?
🚫 Lỗi phổ biến #1 Tin rằng "AI thông minh, tự hiểu được". Thực tế: AI chỉ thấy các con số và tên cột. Nó sẽ đoán — và đoán sai.

Context không phải 1 câu — là quá trình

Nhiều người tưởng dùng AI là "nói 1 câu, AI ra kết quả luôn". Với data phức tạp (2000 cột × 200k dòng), điều đó không khả thi. Thay vào đó, bạn xây context qua vài lượt tương tác:

  1. Đưa nền: mention 3 file setup + file data → AI đọc hiểu cấu trúc
  2. Yêu cầu kiểm tra: "bạn đã hiểu cột profile-qbirthyear chưa?" → AI trả lời, nếu sai thì bổ sung
  3. Thêm rule/bổ sung: mention file rule Excel, bảng merge ngành... → AI tích hợp
  4. Yêu cầu xử lý: áp rule lên data → xem kết quả → tinh chỉnh

Chương 1 Môi trường & vì sao Excel/PQ "tắc thở"

Hiểu vì sao workflow cũ (Excel + Power Query) không chịu nổi data 2000 cột × 200k dòng — và vì sao Python (do AI sinh) là lời giải.

Nỗi đau thực tế của team DA

Workflow hiện tại: tải data CSV full → import Excel → thêm 20-50 cột rule bằng công thức Excel → tổng hợp ra cột phán quyết. Vấn đề:

Tình huốngExcel / Power QueryPython (AI sinh code)
2000 cột × 200k dòngExcel treo, PQ tính rất lâuChạy trong vài giây – vài phút
Thêm 1 cột rule mới (công thức phức tạp)Kéo công thức xuống 200k dòng → đơ máy1 dòng code, chạy tức thì
Đổi rule (vd ngưỡng năm đổi)Sửa công thức toàn file → chậm + dễ saiSửa 1 dòng code, chạy lại

⚠️ Điểm nghẽn Excel/PQ giới hạn RAM và xử lý từng dòng. Khi cột nhiều (2000) + dòng nhiều (200k) + công thức phức tạp (lồng nhau) → bộ nhớ cạn, máy đơ. Python xử lý theo cột (vector hóa) nên không bị vấn đề này.

Mỗi đợt khảo sát, hệ thống (survey platform) xuất về 3 file "hướng dẫn sử dụng". Đây là nền để AI giải mã data — không phải tất cả những gì AI cần.

Chương 3 ★ Quy trình tương tác & đưa rule cho AI

Không phải "1 phát ăn ngay" — đây là quy trình qua lại giữa bạn và AI. Chia lượt để bắt lỗi sớm, AI "học" đúng data từng bước.

Quy trình 4 lượt tương tác

Lượt 1 — Mention nền + yêu cầu đọc hiểu

📋 Lượt 1 — mention file + đọc hiểu quy trình
Tôi là Data Analyst. Đính kèm 3 file setup + data của đợt khảo sát: - questionnaire.csv, survey-structure.csv, behavior.csv - data_q3_2025.csv Hãy đọc 3 file setup để hiểu cấu trúc, rồi check vài cột data (profile-qbirthyear, profile-qyear-of-study) để xác nhận bạn đọc đúng cách. Tóm tắt lại: bạn hiểu cột nào nghĩa là gì, quy ước lưu data thế nào.

Lượt 2 — Kiểm tra hiểu đúng + bổ sung

Đọc tóm tắt của AI. Nếu đúng → tiếp. Nếu sai (vd AI hiểu nhầm giá trị) → sửa: "không phải vậy, cột X có giá trị...". Đây là điểm QA quan trọng — đảm bảo AI vào đúng bài trước khi làm việc thật.

Lượt 3 — Đưa rule + file bổ sung

📋 Lượt 3 — mention file rule + mô tả quy trình
Tốt, bạn đã hiểu đúng. Giờ tôi đính kèm thêm: - rule_definitions.xlsx → file rule của tôi (mỗi dòng = 1 rule) - industry_merge.csv → bảng gom ngành để dùng cho rule phân nhóm Danh sách rule chính: 1. rule_sayso_2007: "SV sinh 2007 mà năm 3-4 → nói xạo" 2. rule_top_uni_it: "Trường top (xem industry_merge) AND thích ngành IT" Hãy đọc 2 file mới, kết hợp với context từ lượt 1, rồi áp các rule lên data. In 5 dòng ví dụ mỗi rule để tôi kiểm tra trước khi chạy full.

Lượt 4 — Xem kết quả + tinh chỉnh

Sau khi AI áp rule, xem kết quả. Tỷ lệ phạm bất thường? Rule nào quá lỏng/khắt? → yêu cầu AI điều chỉnh. Đây là lượt phản hồi, không phải viết mới.

🎯 Tại sao chia lượt? Nhồi 4 việc vào 1 câu = AI dễ hiểu sai 1 chỗ → sai cả chain. Chia lượt giúp bạn bắt lỗi ở từng bước, AI "học" dần đúng data. Mất thêm 2-3 lượt nhưng tiết kiệm hàng giờ sửa sai.

Mô tả rule cho AI

Mỗi rule chỉ cần 2 thứ — bạn chưa cần biết viết công thức, AI viết cho:

  1. Mô tả nghiệp vụ tiếng Việt: "SV sinh 2007 mà năm 3-4 → nói xạo"
  2. Chỉ ra cột liên quan: profile-qbirthyear, profile-qyear-of-study

AI tự đọc setup để biết cách truy cập cột, tự viết code. Rule phức tạp bao nhiêu cũng được — miễn mô tả rõ.

💡 Thường tôi chỉ mention 3 file rồi nói AI đọc để hiểu context Đó là lượt 1. Sau khi AI tóm tắt đúng, tôi mới mention file data + yêu cầu xử lý. Không nhồi tất cả vào 1 lần.

★ Nhờ AI ghi nhớ context vào file MD

Sau khi AI đã hiểu đúng data + rule, bảo nó ghi lại vào file MD để dùng cho lần sau — không phải giải thích lại từ đầu.

Vấn đề: mỗi lần chat mới lại phải giải thích lại

Mỗi cuộc chat mới, AI "quên" hết. Nếu lần sau bạn muốn review/đổi rule, lại phải mention 3 file + giải thích cấu trúc từ đầu — mất thời gian. Giải pháp: nhờ AI ghi nhớ vào file MD.

📋 Prompt — nhờ AI ghi nhớ context vào MD copy-paste
Tốt, bạn đã hiểu đúng cấu trúc data + các rule của đợt khảo sát này. Hãy TỰ ĐỘNG ghi chú tất cả context vào các file MD tương ứng để truy xuất về sau: 1. context_q3_2025.md — tóm tắt: cấu trúc bộ khảo sát, cách đọc từng cột chính, quy ước lưu data 2. rules_q3_2025.md — danh sách rule: mỗi rule kèm mô tả + cột liên quan + logic 3. README.md — mục lục: file nào chứa gì, cách dùng Yêu cầu: - Viết rõ ràng, có cấu trúc, tiếng Việt - Đủ chi tiết để lần sau (hoặc đồng nghiệp) chỉ cần đọc MD là hiểu — không cần hỏi lại - Tôi sẽ lưu các file này vào folder dự án
✅ Lợi ích Lần sau review/đổi rule, bạn chỉ cần mention file MD + hỏi: "đọc context_q3_2025.md, rồi cập nhật rule X". AI nắm ngay bối cảnh — không phải đi quét lại 3 file setup + giải thích từ đầu.

Khi nào nhờ AI ghi nhớ?

  • Sau khi AI đã hiểu đúng data (qua lượt 1-2) → ghi context
  • Sau khi danh sách rule ổn định → ghi rules.md
  • Mỗi lần đổi rule → yêu cầu AI cập nhật MD tương ứng
🎯 Nguyên tắc Context và rule là tài sản dự án — không phải tạm thời trong 1 cuộc chat. Lưu thành MD, dùng lại cho mọi lần sau, chia sẻ đồng nghiệp, commit lên Git. AI tự động ghi chú, bạn chỉ yêu cầu.

Chương 5 Nhờ AI giải mã data file

Bước đầu với mỗi data file: đừng vội viết rule — để AI đọc 3 file setup để hiểu cấu trúc, rồi tóm tắt lại cho bạn các "khối" câu hỏi.

Tại sao cần "giải mã" trước?

Data file có ~2000 cột với tên mã hóa như profile-qbirthyear, eba-most-attractive — bạn không thể nhớ hết. AI đọc 3 file setup rồi tóm tắt cấu trúc (phần nào có câu gì, loại gì) giúp bạn định vị nhanh.

📋 Prompt — nhờ AI giải mã & tóm tắt cấu trúc data copy-paste
Bạn là Data Analyst. Tôi đính kèm 3 file setup: questionnaire.csv, survey-structure.csv, behavior.csv. Hãy đọc và tóm tắt cấu trúc bộ khảo sát này: 1. Có bao nhiêu phần (part)? Mỗi phần chứa câu hỏi gì? 2. Liệt kê các câu hỏi theo WIDGET TYPE: multiple_choice (chọn nhiều), scale (thang), single_choice, grid... 3. Với mỗi câu multiple_choice: liệt kê các option (code _o...) kèm nhãn tiếng Việt 4. Với mỗi câu scale: cho biết thang điểm (1-5? 1-10?) 5. Chỉ ra các câu có ràng buộc đặc biệt (từ behavior.csv: va_at_least, dlogic_show...) Mục đích: tôi cần hiểu cấu trúc để viết rule kiểm tra respondent. Tóm tắt bằng tiếng Việt, có cấu trúc rõ ràng.
✅ Kết quả mong đợi AI trả về bản tóm tắt dạng: "Phần 0 (profile): năm sinh (list_box, 30 option 1985-2011), năm học (list_box 1-4), khu vực... Phần 3 (EBA): ngành yêu thích (multiple_choice 15 option), lý do (textarea)..." → bạn biết ngay câu nào dùng để viết rule nào.
💡 Mẹo Nếu data quá lớn (200k dòng) không upload được toàn bộ lên chat, hãy tạo file data mẫu 100 dòng đầu (đủ các loại respondent) để AI đọc cấu trúc. Khi viết rule xong, chạy code trên file thật ở máy.

Chương 6 ★ Nhờ AI apply 20-50 cột rule

Trọng tâm của hướng dẫn. Đây là việc tốn nhiều thời gian nhất trên Excel — giờ giao cho AI. Bạn chỉ cần mô tả rule + chỉ cột liên quan.

Quy trình apply rule với AI

  1. Viết danh sách rule (mô tả tiếng Việt + cột liên quan) — xem Chương 3
  2. Đưa AI 3 file setup + data để AI hiểu cột
  3. Nhờ AI sinh code tạo từng cột rule_*
  4. Verify: in 5 dòng ví dụ trước/sau mỗi rule
  5. Chạy trên data thật (ở máy, qua Colab hoặc VS Code)

Ví dụ rule thật: "SV 2007 năm 3-4 → nói xạo"

💡 Bối cảnh Sinh viên sinh 2007 thì năm 2025 mới 18 tuổi, chưa thể là sinh viên năm 3-4 đại học. Rule này phát hiện respondent có khả năng điền bừa.
📋 Prompt — áp 1 rule kiểm tra "nói xạo" copy-paste
Bạn là Data Analyst. Đính kèm: data.csv + 3 file setup (đã hiểu cấu trúc từ Chương 5). [RULE: sayso_2007_year34] Mô tả: "Sinh viên sinh năm 2007 nhưng đang học năm 3 hoặc năm 4 → khả năng nói xạo" Cột liên quan: - profile-qbirthyear (năm sinh) - profile-qyear-of-study (năm học, giá trị 1-4) Viết code Python tạo cột rule_sayso_2007_year34: - = 1 (phạm rule) nếu: respondent sinh 2007 AND year-of-study in [3,4] - = 0 (ok) nếu không Logic check (mock code): if (birthyear=2007 AND yearofstudy in [3,4], 1, 0) Yêu cầu: - Tự so questionnaire.csv để biết cách đọc giá trị "sinh 2007" trong cột profile-qbirthyear - In 5 dòng ví dụ (cả trước/sau khi apply) để tôi verify - Giải thích cách bạn xác định "sinh 2007" từ data

Áp nhiều rule cùng lúc (batch)

Khi có 20-50 rule, viết từng prompt rất lâu. Gom thành 1 danh sách, AI sinh code tạo tất cả cột cùng lúc.

📋 Prompt — apply batch 20-50 rule copy-paste
Bạn là Data Analyst. Đính kèm: data.csv + 3 file setup. [DANH SÁCH RULE - mỗi rule tạo 1 cột mới] 1. rule_sayso_2007_year34: "SV sinh 2007 mà năm 3-4" → cột: qbirthyear, qyear-of-study 2. rule_top_uni_it: "Học trường top (list dưới) AND thích ngành IT" - Trường top: tự so questionnaire để xác định mã trường top - Ngành IT: tự so questionnaire để xác định mã ngành IT 3. rule_fast_response: "Thời gian trả lời < 3 phút" - Cột: submit_time, start_time 4. rule_missing_profile: "Thiếu >2 câu profile bắt buộc" - Cột: qbirthyear, qgender, qregion, quniversity-* 5. ... (viết tiếp các rule còn lại) [YÊU CẦU] - Viết 1 script Python tạo TẤT CẢ cột rule_* trên - Mỗi rule = 1 cột giá trị 1/0 (1=phạm, 0=ok) trừ khi ghi khác - Xử lý NaN an toàn (NaN không tính là "phạm") - In: số respondent phạm mỗi rule + 3 ví dụ mỗi rule - Giải thích ngắn mỗi rule bằng tiếng Việt Tôi sẽ chạy script trên data thật (200k dòng).
⚠️ Bẫy khi đọc cột Mỗi loại câu hỏi lưu data khác nhau (chọn 1 vs chọn nhiều vs thang điểm). Bạn không cần phân biệt — chỉ cần đính kèm đủ 3 file setup, AI tự so questionnaire để đọc đúng từng cột. Nếu AI đọc sai, gửi lại 5 dòng data mẫu để nó tự kiểm chứng.
🎯 Nguyên tắc cốt lõi Bạn chưa cần biết viết công thức — AI viết cho. Việc của bạn: (1) mô tả rule bằng tiếng Việt, (2) chỉ ra cột liên quan. AI tự đọc setup để biết cách truy cập cột, rồi viết code. Sau đó hãy nhờ AI giải thích đoạn code để bạn hiểu — biết thế mới bắt được lỗi AI và yêu cầu sửa. Rule phức tạp bao nhiêu cũng được, miễn mô tả rõ.

Chương 7 ★ Nhờ AI tạo cột phán quyết cuối

Sau khi có 20-50 cột rule, bước cuối: tổng hợp thành 1 cột phán quyết (QUALIFIED / REVIEW / REJECT) theo quy tắc của từng dự án.

Cột phán quyết = tổng hợp các rule

Tùy dự án, cách phán quyết khác nhau. Một số dạng phổ biến:

Dạng phán quyếtMô tảVí dụ
Đếm rule pass≥80% rule pass → đủ chuẩnQUALIFIED nếu ≥40/50 rule = 0 (ok)
Rule chặn (hard fail)Phạm 1 rule quan trọng → loại luônREJECT nếu sayso_2007=1 (dù các rule khác ok)
Tính tổng điểmMỗi rule có trọng số, cộng lạiĐiểm > ngưỡng → đủ
CompositeKết hợp nhiều cách trênHard fail + điểm + quota
📋 Prompt — tạo cột phán quyết cuối copy-paste
Bạn là Data Analyst. Data đã có 30 cột rule_* (1=phạm, 0=ok). [QUY TẮC PHÁN QUYẾT - composite] 1. HARD FAIL: nếu phạm 1 trong các rule nghiêm trọng → REJECT ngay - rule_sayso_2007_year34, rule_fast_response, rule_missing_profile 2. ĐIỂM: tính total_score = số rule OK (đếm rule_*=0) - Có 27 rule thường (trừ 3 hard fail) 3. PHÂN LOẠI: - QUALIFIED: không hard fail AND total_score >= 22/27 (≥80%) - REVIEW: không hard fail AND total_score 14-21 (50-80%) - REJECT: hard fail OR total_score < 14 Viết code Python: 1. Tạo cột final_verdict theo quy tắc trên 2. In phân bố: bao nhiêu % QUALIFIED/REVIEW/REJECT 3. In top lý do REJECT (rule nào hay bị phạm nhất) 4. Xuất file kết quả có thêm cột final_verdict
✅ Thói quen DA chuyên nghiệp Luôn yêu cầu AI in phân bố + top lý do REJECT. Nếu 90% REJECT → có thể rule quá khắt khe, cần xem lại. Nếu 0% REJECT → có thể rule lỏng quá. Phân bố giúp bạn "cảm" được chất lượng.
💡 Linh hoạt theo dự án Phần [QUY TẮC PHÁN QUYẾT] thay đổi theo từng dự án — không hard code 1 cách. Mô tả logic cụ thể của dự án hiện tại, AI dịch sang code.

Chương 9 ★ Nhờ AI check code rule cũ

Code sinh ra không hoàn hảo ngay. Khi kết quả "lạ" hoặc nghi ngờ, nhờ AI review lại.

Khi nào cần nhờ AI review code?

  • Tỷ lệ REJECT bất thường (vd: 95% respondent bị loại → nghi rule sai)
  • Một rule vi phạm quá nhiều / quá ít so với kỳ vọng
  • Đổi rule, muốn chắc code cũ còn đúng
  • Trước khi đưa cho đồng nghiệp dùng chung
📋 Prompt — nhờ AI review code rule cũ copy-paste
Bạn là Senior Data Analyst. Tôi có code Python áp rule lên data khảo sát. Đính kèm 3 file setup + data mẫu. Đây là code: {DÁN CODE} Tôi NGHI NGỜ kết quả sai: {mô tả triệu chứng, vd: "rule_sayso_2007 vi phạm 0% trong khi kỳ vọng ~5%"} Hãy REVIEW và chỉ ra: 1. Lỗi đọc cột: có đọc sai cách data lưu (so với questionnaire) không? Gửi 5 dòng data mẫu để bạn tự kiểm chứng. 2. Lỗi logic: điều kiện if có đúng không? NaN xử lý đúng chưa? 3. Edge case: respondent không có câu trả lời (NaN) bị tính ra sao? Với mỗi vấn đề: giải thích + code đã sửa.
⚠️ Đừng nhờ AI "tối ưu chung chung" Prompt mơ hồ "kiểm tra giúp" ra kết quả nông. Luôn dán 3 file setup + mô tả triệu chứng cụ thể (vd: "rule X vi phạm 0% mà kỳ vọng ~5%").

Lỗi thường gặp khi apply rule

  • Đọc sai cách lưu data: không so questionnaire → hiểu sai giá trị cột. Khắc phục: luôn đính kèm 3 file setup
  • NaN: respondent không trả lời → NaN, nếu code không xử lý → tính sai
  • Edge case: giá trị bất thường (ngoài dự kiến) → AI cần check
  • Quy chiếu câu cha: option thuộc câu nào (xem Belong Question trong structure)

Chương 12 ★ Nhờ AI commit lên Git — chưa biết git cũng làm được

Lưu code + context lên GitHub/GitLab để backup, chia sẻ đồng nghiệp, xem lại lịch sử. Bạn chưa thuộc lệnh git cũng không sao — nhờ AI viết lệnh, rồi nhờ AI giải thích để hiểu và biết AI sai chỗ nào mà sửa.
💡 Git là gì — cho Data Analyst (1 câu) Git = công cụ lưu phiên bản code, giống Google Drive cho tài liệu. GitHub/GitLab = trang web đặt code đó để team cùng xem. Bạn chưa biết git cũng được — nhờ AI sinh lệnh, rồi nhờ AI giải thích từng lệnh để dần hiểu.
