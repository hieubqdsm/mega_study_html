CH 1 Unity là gì & vì sao đáng học

Engine phổ biến nhất thế giới — và C# là kỹ năng dùng được cả ngoài game.

Unity là game engine thương mại phổ biến nhất hành tinh: phần lớn game mobile, vô số game indie và cả những tựa 3D cỡ vừa được làm bằng Unity. Ngôn ngữ lập trình là C# — ngôn ngữ của cả hệ sinh thái Microsoft (.NET), nên kiến thức học ở đây chuyển dịch được sang làm app, web, tự động hoá. Giấy phép Personal: miễn phí cho cá nhân/doanh thu dưới 200k USD/năm.

Phiên bản dùng trong khóa

Unity 6 LTS (6000.x) — bản hỗ trợ dài hạn, tài liệu Unity Learn mới nhất đã cập nhật theo (Haunted House dạy trên 6.3). Gặp tutorial cũ 2019–2022 vẫn đọc được, chỉ nhớ vài chỗ đổi tên — quan trọng nhất: Rigidbody.velocity giờ là linearVelocity ở Unity 6.

CH 2 Cài đặt — Unity Hub & project đầu tiên

Hub là "trạm điều khiển": cài Editor, quản lý phiên bản, mở project.

Ba bước cài

  1. Tải Unity Hub từ unity.com/download → cài → đăng ký Unity ID miễn phí (cần để dùng Personal license).
  2. Trong Hub, tab Installs → Install Editor → chọn Unity 6 LTS → modular: nếu chưa có IDE, tick thêm Visual Studio (Windows) / VS Code (các nền). ~vài GB, làm cà phê.
  3. Hub → New project → chọn template Universal 2D (khóa đi tới đây trước) hoặc Universal 3D (URP) → đặt tên hoc-unity → Create.
Template nào cho người mới?Universal 2D/3D (URP) = render pipeline hiện đại, template mặc định của Unity 6 — dùng luôn. "Built-in" chỉ gặp lại khi theo tutorial cũ. Kỳ này không cần quan tâm HD.

Lần đầu mở project

  • Mặc định có scene Assets/Scenes/SampleScene — Ctrl+S lưu scene bất cứ lúc nào.
  • Bấm ▶ Play (Ctrl+P) để "chạy game" — khác Godot: Unity luôn chạy từ scene đang mở, không phân biệt F5/F6. Pause ⏸ (Ctrl+Shift+P) đóng băng, Step ⏭ tiến từng frame — debug thân yêu.
  • Thử ngay: Hierarchy (trái trên) → chuột phải → 2D Object → Sprites → Square → bấm Play — một ô vuông hiện ở Game view. Bạn vừa "làm game".
Chỉnh sửa trong Play Mode = mất khi thoátĐang bấm Play mà sửa scene thì thay đổi bị vứt bỏ khi dừng (Unity cảnh báo bằng viền xanh). Quy tắc: dừng Play rồi mới sửa — hoặc cố tình dùng để thử số liệu nhanh.

CH 4 GameObject, Component & Prefab — viên gạch của Unity

Khác Godot "mọi thứ là node trong cây" — Unity: "mọi thứ là GameObject + component ghép".

GameObject = vật chứa, Component = hành vi

Một GameObject tự thân chẳng làm gì — nó là hộp chứa component. Mỗi component đúng 1 việc: Transform (vị trí/xoay/kích thước — luôn có sẵn, xóa không được), SpriteRenderer (hiện ảnh 2D), Rigidbody2D (vật lý), BoxCollider2D (va chạm), AudioSource (âm thanh)... và script bạn viết cũng là một component.

Inspector của "Ruby" nhìn như thế này
Ruby (GameObject)
├─ Transform            # luôn có — Position / Rotation / Scale
├─ SpriteRenderer       # hiện sprite Ruby
├─ Rigidbody2D         # tham gia vật lý 2D
├─ CircleCollider2D    # vùng va chạm tròn
└─ RubyController (Script)  # code di chuyển — bạn viết ở CH16

Thêm component: nút Add Component dưới cùng Inspector (hoặc chuột phải object → COMPONENT). Bánh răng ⚙ của component → Remove Component / Reset.

Prefab — khuôn tái sử dụng

Kéo GameObject từ Hierarchy vào cửa sổ Project → thành file .prefab (màu xanh). Từ đó kéo ra bao nhiêu bản trong các scene cũng được. Bấm đúp prefab → vào Prefab Mode sửa khuôn gốc → mọi bản sinh ra tự cập nhật. Đây chính là "instance scene" của Godot.

Cha–con, Tag & Layer

  • Kéo object A thả vào object B trong Hierarchy → A thành con của B; con kế thừa chuyển động của cha (tay theo thân).
  • Tag: nhãn định danh ("Player", "Enemy") — soi bằng CompareTag("Player").
  • Layer: nhóm phục vụ render thứ tự & bảng va chạm (Layer Collision Matrix trong Project Settings → Physics 2D) — trò "đạn không bắn đồng đội" làm bằng này.
Đối chiếu Godot ↔ UnityNode ≈ GameObject + các component gộp lại · Scene (.tscn) ≈ Scene + Prefab · Inspector giống nhau · Signal ≈ UnityEvent (Button.OnClick) + C# event/delegate. Ai học từ khóa Godot sẽ thấy L1–L2 của khóa này quen quen một cách dễ chịu.
🗂 Luyện trong Component LabMở Component Lab → chọn mục tiêu Player (Ruby) → thêm Rigidbody2D, CircleCollider2D, SpriteRenderer, Script → Kiểm tra. Làm đủ 4 mục tiêu (Robot, Enemy, Main Camera) để quen tay "Add Component" trước khi đụng Unity thật.
✏️ Thực hành 4.1 dễ

Tạo GameObject trống (chuột phải → Create Empty), thêm component AudioSource và một Script mới tên Hello (Add Component → New Script). Vào Play — Console in gì? (Chưa có gì — script trắng; CH5 sẽ làm nó nói chuyện.)

CH 5 Script đầu tiên

MonoBehaviour — cây cầu giữa code C# của bạn và thế giới Unity.

Tạo & gắn script

Project → chuột phải folder Scripts → Create → Scripting → MonoBehaviour Script → đặt tên Hello (tên class PHẢI trùng tên file). Kéo file script thả vào GameObject trong Hierarchy — giờ script là một component của object đó.

Hello.cs
using UnityEngine;

public class Hello : MonoBehaviour     // kế thừa MonoBehaviour mới "hưởng" Unity
{
    public float speed = 5f;              // public → hiện trong Inspector!

    void Start()                          // chạy ĐÚNG 1 LẦN, trước frame đầu
    {
        Debug.Log("Xin chào Unity!");
    }

    void Update()                         // chạy MỖI frame (~60 lần/giây)
    {
        transform.position += Vector3.right * speed * Time.deltaTime;
    }
}

Bấm Play → Console hiện dòng chữ, object trôi dần sang phải. Bạn vừa viết chương trình C# đầu tiên! 🎉

CH 8 OOP căn bản cho game

Class, public/private, GetComponent — 3 thứ dùng mỗi ngày trong Unity.

Class = bản vẽ

class gói field (dữ liệu) + method (hành vi). public = ai cũng dùng được; private (mặc định) = chỉ trong class. Mọi script Unity đều là class kế thừa MonoBehaviour — nhờ thế mới có Start/Update và hiện được trong Inspector.

GetComponent — nói chuyện với component cạnh

LayComponent.cs
public class LayComponent : MonoBehaviour
{
    private Rigidbody2D rb;          // cache — chuẩn mực

    void Start()
    {
        rb = GetComponent<Rigidbody2D>();   // tìm trên CÙNG object
    }

    void Update()
    {
        // Bắn ray tìm component trên object KHÁC:
        var ruby = GameObject.FindWithTag("Player")
                     .GetComponent<RubyController>();
    }
}
GetComponent mỗi frame = chậmTìm component là thao tác tốn kém — gọi 1 lần trong Start() bỏ vào field (cache) như trên, đừng gọi trong Update. Nguyên tắc số 1 hiệu năng Unity cho người mới.

Vector2/3 — kiểu "quốc dân"

  • Vector3(x, y, z); 2D dùng Vector3 hay Vector2 đều được (z=0). Hằng có sẵn: Vector3.right/left/up/down/zero/one.
  • Hay dùng: v.normalized (độ dài 1), Vector3.Distance(a,b), Vector3.Lerp(a, b, t) (trôi mượt), Vector3.Angle(a,b).
  • Xoay 2D: Quaternion.Euler(0, 0, gocDo) — góc quanh trục Z.

CH 9 Vòng lặp game, delta & input

Update vs FixedUpdate, Time.deltaTime, và đọc phím người chơi.

deltaTime — quy tắc vàng đầu tiên

Máy 30fps và 144fps chạy cùng code thì chuyển động lệch nhau 5 lần, trừ khi nhân Time.deltaTime (số giây frame trước kéo dài) — biến "đơn vị/frame" thành "đơn vị/giây":

DiChuyen.cs
void Update()
{
    // ĐÚNG: nhân deltaTime — tốc độ như nhau mọi máy
    transform.position += Vector3.right * speed * Time.deltaTime;
}
void FixedUpdate()
{
    // Vật lý (Rigidbody, lực) đặt ở ĐÂY — timestep cố định 0.02s
    rb.AddForce(Vector2.up * luc);
}

CH 10 Sprite & Sprite Editor

Đưa ảnh vào game — và cắt spritesheet thành từng động tác.

Import & dùng

  1. Kéo file PNG vào folder Sprites trong Project — Unity tự import.
  2. Kéo sprite từ Project thẳng vào Scene → tự tạo GameObject có SpriteRenderer.
  3. Chọn file → tab Inspector chỉnh import: Filter Mode: Point (no filter) cho pixel art + Compression: None (đỡ mờ).
Pixels Per Unit (PPU)Số pixel ảnh ứng với 1 unit thế giới (mặc định 100). Sprite 32×32 với PPU 32 sẽ to bằng sprite 100×100 với PPU 100. Chọn 1 PPU cho cả project (pixel art thường = kích thước tile, vd 16/32/64) để mọi thứ khớp nhau.

Sprite Editor — cắt spritesheet

Chọn spritesheet (ảnh chứa nhiều frame) → Inspector → Sprite Editor → Slice: Automatic (tự tách theo viền) hoặc Grid By Cell Size (lưới cố định 32×32 — chuẩn pixel art) → Slice → Apply. Ảnh 1 file bỗng thành mớ sprite con (mũi tên mở rộng cạnh tên file), sẵn sàng cho animation ở CH12.

Sắp chồng nhau — Sorting

2D không có "Z" như 3D — thứ tự vẽ do Sorting Layer (đặt tên layer: Background → Characters → FX) và trong cùng layer thì Order in Layer (số cao vẽ trên). SpriteRenderer còn có flipX (lật hướng nhìn), color (nhuộm đỏ khi trúng đòn).

CH 11 Tilemap & Tile Palette

Vẽ map cả buổi trong 10 phút — khỏi đặt từng ô thủ công.

Quy trình 4 bước

  1. Hierarchy → chuột phải → 2D Object → Tilemap → Rectangular (tạo Grid cha + Tilemap con).
  2. Window → 2D → Tile Palette → Create New Palette (đặt folder) → kéo spritesheet vào vùng palette — Unity hỏi cắt theo grid, khớp cỡ ô là ra bộ gạch.
  3. Trong palette bấm chọn ô gạch → quét chuột trên Scene để vẽ; chuột phải xóa; Shift+chuột hút mẫu.
  4. Va chạm: chọn Tilemap → Add Component Tilemap Collider 2D (gạch nào cũng thành tường) — nên thêm tiếp Composite Collider 2D + Rigidbody2D (Body Type: Static) để gộp biên liền mạch, vật thể trượt mượt.
Nhiều lớp TilemapTạo 2 Tilemap con trong cùng Grid: Background (không collider — cỏ, nền) và Ground (có collider — tường, gai). Giữ sorting layer khác nhau. Vẽ occlusion kiểu "phòng trong nhà"? Dùng thêm layer "Walls" vẽ trên đầu nhân vật.
Đối chiếu GodotTile Palette ≈ panel TileSet của Godot; Tilemap Collider 2D ≈ Physics Layers trong TileSet. Rule Tile (gạch thông minh tự chọn viền) là package "2D Tilemap Extras" — Godot không có sẵn tương đương.

CH 12 Animation — Animator Controller

Máy trạng thái hoạt hình: Idle ↔ Walk ↔ Hit, điều khiển từ code.

Tạo animation đầu tiên

  1. Chọn object có SpriteRenderer → Window → Animation → Animation (đặt cạnh Console cho tiện).
  2. Bấm Create → lưu clip Walk trong folder Animations.
  3. Kéo dàn frame (từ spritesheet CH10) vào timeline; chỉnh Samples (fps) 8–12 cho pixel art; bấm ▶ xem thử.
  4. Tạo thêm clip Idle (dropdown clip → Create New Clip). Mỗi object có 1 Animator Controller tự sinh.

Máy trạng thái & điều khiển từ code

Window → Animation → Animator: mỗi clip là 1 state (màu cam = mặc định). Kéo mũi tên giữa các state = transition. Tạo Parameter (vd Bool isWalking, Trigger hit) rồi ở transition đặt Condition dựa theo parameter:

AnimTuCode.cs
private Animator anim;                    // cache trong Start()

void Update()
{
    anim.SetBool("isWalking", x != 0 || y != 0);
    anim.SetTrigger("hit");                // bắn 1 lần rồi tự reset
    anim.SetFloat("speed", tocDoHienTai);      // blend mượt theo số
}
Cái bẫy Exit TimeTransition mặc định có Exit Time (chờ hết clip mới đổi) — khi muốn đổi state ngay theo input, chọn transition và bỏ tick Has Exit Time, điều khiển hoàn toàn bằng Conditions.

CH 13 UI — Canvas, TextMeshPro & nút bấm

Điểm số, thanh máu, nút Start — phần khiến game "thật" hẳn ra.

Canvas — mẹ của mọi UI

Hierarchy → chuột phải → UI → bất kỳ thứ gì (Text, Button, Image...) → Unity tự tạo Canvas (chế độ Screen Space - Overlay: UI vẽ trên gameplay, không bị camera kéo) + EventSystem (thụ lý bấm/phím cho UI). Mọi UI phải nằm trong Canvas.

  • Text - TextMeshPro: chữ đẹp — lần đầu dùng sẽ hỏi Import TMP Essentials → đồng ý. Lần lượt: đặt chữ, cỡ font, màu, alignment.
  • Anchor (hộp neo khi chọn UI): neo về góc/giữa màn để co giãn đẹp; giữ Alt + bấm anchor = căn position luôn.
  • Button: khung On Click () trong Inspector → kéo GameObject chứa script → chọn hàm public — không cần viết code nối (khác Godot nối signal tay).

CH 15 Vật lý 2D & trigger — mảnh ghép quan trọng nhất

Rigidbody2D, Collider, Is Trigger — 90% tương tác game 2D làm bằng này.

Bộ ba Rigidbody2D + Collider + (thỉnh thoảng) Script

Thành phầnVai trò
Rigidbody2D DynamicEngine mô phỏng trọn vẹn (rơi, bị đẩy) — thùng, vật phẩm văng
Rigidbody2D KinematicBạn tự điều khiển qua code — nhân vật Ruby dùng kiểu này

Di chuyển nhân vật chuẩn Ruby

RubyController.cs (lõi)
public class RubyController : MonoBehaviour
{
    public float tocDo = 3f;
    private Rigidbody2D rb;

    void Start() { rb = GetComponent<Rigidbody2D>(); }

    void FixedUpdate()                          // vật lý — dùng FixedUpdate
    {
        float x = Input.GetAxisRaw("Horizontal");
        float y = Input.GetAxisRaw("Vertical");
        var v = new Vector2(x, y).normalized * tocDo;
        rb.linearVelocity = v;                  // Unity 6 (bản cũ là rb.velocity)
    }
}
Unity 6 đổi tênrb2d.velocity → rb.linearVelocity (cả 2D lẫn 3D). Tutorial Ruby chính thức viết bằng bản cũ — gặp velocity đỏ lỗi thì đổi thành linearVelocity là xong.

Trigger — "cảm biến" nhiều nhất dùng

SuaRobot.cs
// Gắn trên ROBOT (Collider tick Is Trigger). Ruby (Rigidbody2D) đi vào → hàm tự chạy
void OnTriggerEnter2D(Collider2D other)
{
    if (other.CompareTag("Player"))
    {
        other.GetComponent<RubyController>().SuaRobot(1);
        Destroy(gameObject);                    // robot biến mất
    }
}
// Bộ họ trigger: OnTriggerEnter2D / Stay2D / Exit2D (vào / đứng trong / rời)
Trigger vs Collider thườngCollider thường = chặn nhau (tường). Trigger = xuyên qua nhưng "biết" (nhặt đồ, vùng gai, cửa). Quy tắc: ít nhất 1 trong 2 phải có Rigidbody2D thì trigger mới hoạt động — người chơi có sẵn là đủ.

PlayerController.cs (khung)
public class PlayerController : MonoBehaviour
{
    public float tocDo = 4f;

    void Update()
    {
        float x = Input.GetAxisRaw("Horizontal");
        float z = Input.GetAxisRaw("Vertical");
        var huong = new Vector3(x, 0, z).normalized;
        transform.position += huong * tocDo * Time.deltaTime;
        if (huong != Vector3.zero)
            transform.rotation = Quaternion.LookRotation(huong);   // quay mặt theo hướng đi
    }
}

CH 19 "Nhà Ma" #2 — Kẻ địch, kết thúc & audio

Quỷ đá gargoyle — canh gác kiểu "quét ánh nhìn"

  • Phát hiện player = góc nhìn + khoảng cách: trong update của enemy, tính vector tới player, so Vector3.Angle(transform.forward, denPlayer) < góc nhìn (vd 45°) VÀ Vector3.Distance < tầm (vd 8f) → phát hiện!
  • Đuổi theo bằng NavMeshAgent: Window → AI → Navigation → đánh dấu sàn là Walkable → Bake; enemy thêm component NavMeshAgent; khi phát hiện: agent.SetDestination(player.position); — quỷ tự tìm đường né vật cản.
  • Chạm player (OnTriggerEnter trong Capsule Collider to bản của enemy) → thua, hiện "Bị bắt!" + SceneManager.LoadScene(SceneManager.GetActiveScene().name) chơi lại.

void Update()
{
    var denRuby = player.position - transform.position;
    bool trongTam = denRuby.magnitude < tamNhin;
    bool trongGoc = Vector3.Angle(transform.forward, denRuby) < 45f;
    if (trongTam && trongGoc)          // PHÁT HIỆN — đuổi!
        agent.SetDestination(player.position);
    else
        agent.ResetPath();                // mất dấu — về nghỉ
}

🧠 Kiểm tra kiến thức sau 21 chương

1. Trong Unity, "hành vi" của một GameObject (hiện ảnh, vật lý, va chạm...) đến từ đâu?

Unity: GameObject = vật chứa, hành vi nằm trong component gắn vào. Khác Godot (node lồng cây). CH4.

2. Sửa scene trong lúc đang bấm Play thì chuyện gì xảyra khi dừng Play?

Play Mode là "bản thử": chỉnh sửa bị reset khi dừng (trừ khi dùng công cụ debugger đặc biệt). CH2.

3. Prefab là gì?

Prefab = "instance scene" của Godot: kéo GameObject vào Project để tạo khuôn. CH4.

4. Khai báo float nào đúng cú pháp C#?

Số thập phân mặc định là double — cần suffix f cho float. Quên f là lỗi CS0664 kinh điển. CH6.

5. Vì sao chuyển động trong Update() phải nhân Time.deltaTime?

deltaTime = thời gian frame trước; nhân vào biến "đơn vị/frame" thành "đơn vị/giây". CH9.

6. Vật lý (Rigidbody, AddForce) nên xử lý ở hàm nào?

FixedUpdate chạy 50Hz đều đặn — vật lý ổn định; Update lệch theo fps. CH9.

7. Chuẩn mực khi dùng GetComponent?

Tìm component tốn kém — cache 1 lần. Nguyên tắc hiệu năng số 1. CH8.

8. Muốn "robot biến mất khi Ruby chạm vào", cấu hình + hàm nào đúng?

Trigger = xuyên qua nhưng phát hiện — chuẩn cho nhặt đồ/sửa robot. CH15–16.

9. Unity 6 gọi thuộc tính vận tốc của Rigidbody2D là gì (bản cũ là velocity)?

Unity 6 đổi tên velocity → linearVelocity — tutorial cũ viết velocity sẽ đỏ lỗi, đổi tên là chạy. CH15.

10. Animation: muốn đổi state NGAY theo input (không chờ hết clip), phải làm gì?

Exit Time mặc định chờ hết clip — bỏ tick để parameter (SetBool/SetTrigger) quyết định tức thì. CH12.

11. Quỷ đá phát hiện player bằng cách so gì?

Stealth = tầm nhìn + góc quét; phát hiện rồi mới SetDestination bằng NavMeshAgent. CH19.

12. Muốn có link gửi bạn bè chơi bản WebGL ngay trên trình duyệt?

Build WebGL → upload Unity Play → link chơi ngay. CH20.

L0
6 cửa sổ chính của editor?
Hierarchy · Scene · Game · Inspector · Project · Console.
L0
Component nào có sẵn trên MỌI GameObject, xóa không được?
Transform — vị trí/rotation/scale.
L0
QWER trong Unity làm gì? (giống engine nào đã học?)
Q xem-di chuyển view, W move, E rotate, R scale — y hệt Godot. F = tập trung object.
L0
Tag vs Layer?
Tag = nhãn định danh (CompareTag("Player")). Layer = nhóm cho render + bảng va chạm (đạn không bắn đồng đội).
L1
Start() vs Update() vs FixedUpdate()?
Start: 1 lần đầu. Update: mỗi frame (input, hiển thị). FixedUpdate: 50Hz cố định (vật lý).
L1
Vì sao float x = 0.5; lỗi?
0.5 mặc định là double; float cần suffix f: 0.5f.
L1
public vs [SerializeField] private?
Cả hai hiện trong Inspector; private giữ đóng gói OOP — chuẩn mực là [SerializeField] private.
L1
Nội suy chuỗi trong C#?
Debug.Log($"Máu: {mau}"); — dấu $ phía trước chuỗi.
L1
GetComponent đúng chuẩn?
Gọi 1 lần trong Start() → cache vào field: rb = GetComponent<Rigidbody2D>();
L1
Chờ 1 giây rồi làm gì đó (khác Godot await)?
Invoke("TenHam", 1f); hoặc Coroutine: yield return new WaitForSeconds(1f).
L1
GetAxisRaw vs GetKey?
GetAxisRaw("Horizontal") trả -1/0/1 từ trục (đi chuyển mượt); GetKey/GetKeyDown(KeyCode.X) hỏi phím cụ thể (nhảy, bắn).
L1
Vector3.Distance / .normalized / Lerp?
Khoảng cách 2 điểm / độ dài về 1 giữ hướng / trôi mượt từ a tới b theo t.
L2
Pixels Per Unit quyết định gì?
Bao nhiêu pixel ảnh = 1 unit thế giới. Cả project dùng 1 PPU để mọi sprite khớp.
L2
Sắp xếp vẽ 2D trong Unity?
Sorting Layer trước, rồi Order in Layer (số cao vẽ trên) — 2D không dùng Z.
L2
Tilemap có va chạm bằng cách nào?
Tilemap Collider 2D (+ Composite Collider 2D để gộp biên mượt).
L2
Trigger hoạt động cần điều kiện gì?
ít nhất 1 trong 2 object phải có Rigidbody2D; hàm: OnTriggerEnter2D(Collider2D other).
L2
UI: Button gọi hàm mà không cần code nối?
Inspector → On Click () → kéo GameObject → chọn hàm public (UnityEvent).
L2
Nhạc nền cấu hình thế nào?
AudioSource: Play On Awake ✓ + Loop ✓ + Spatial Blend 0 (2D).
L3
Rigidbody 3D: cách để nhân vật không lăn nhào?
Constraints → Freeze Rotation X/Z (giữ Y nếu cần quay người).
L3
NavMeshAgent dùng để làm gì? Cần setup gì?
Cho enemy tự tìm đường: Window → AI → Navigation → Bake lưới; code agent.SetDestination(player.position).
L3
Quay GameObject nhìn theo hướng đi?
transform.rotation = Quaternion.LookRotation(huong);
L3
WebGL build xong, gửi bạn bè bằng gì?
Upload Unity Play (play.unity.com) — có link chơi ngay trên trình duyệt.
