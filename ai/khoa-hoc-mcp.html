Chương 1 MCP là gì

"USB-C cho AI" — một chuẩn kết nối cho mọi LLM.

Model Context Protocol (MCP) là chuẩn mở do Anthropic công bố (mở nguồn cuối 2024), định nghĩa cách một LLM giao tiếp với dữ liệu & công cụ bên ngoài. Trước MCP, mỗi nền tảng (OpenAI, Anthropic, Google) có một cơ chế function calling riêng → code tool không tái dùng được. MCP thống nhất: viết tool một lần, dùng cho mọi client.

Trước MCPCó MCP
Tool cho OpenAIViết JSON schema riêng1 MCP server dùng chung
Đổi sang ClaudeViết lại toolCắm lại — không sửa code
Đổi sang Llama (local)Lại viết lạiVẫn dùng được
Bảo trìChắp vá, rời rạc khắp appTập trung ở 1 server
Hình dung USB-C Trước USB-C, mỗi điện thoại một loại cáp sạc. MCP làm cho tool của AI giống USB-C: một đầu cắm chuẩn, chạy ở mọi "thiết bị" (Claude, Cursor, GPT, IDE...). Bạn — người viết tool — không phải lo client nào sẽ dùng.
📝 Quiz nhanh
1. MCP giải quyết vấn đề cốt lõi nào?
✅ MCP là chuẩn giao tiếp — thống nhất cách LLM kết nối tool/dữ liệu, giúp code tái dùng giữa các client.

Chương 2 Vấn đề với function calling ad-hoc

Vì sao "tích hợp tool từng app" là ngõ cụt.

Cách cũ (function calling từng nền tảng) là "đảo ngược control": ứng dụng AI hardcode danh sách tool & schema ngay trong code của nó. Hậu quả:

  • Không tái dùng — tool "gửi email" viết cho OpenAI phải viết lại cho Claude.
  • Bảo mật rời rạc — mỗi app tự xử lý quyền, không có chuẩn chung.
  • Khó mở rộng — thêm tool = sửa & deploy lại cả ứng dụng AI.
  • Khóa vendor — đổi provider (GPT→Claude→Llama) = viết lại toàn bộ.
MCP đảo lại control Tool sống trong một server độc lập, app AI chỉ là client gọi qua chuẩn chung. Thêm/sửa tool không cần đụng tới app AI — chỉ restart server.

Chương 3 Kiến trúc Client-Server

3 vai trò — Host, Client, Server.
Vai tròLà gìVí dụ
MCP HostỨng dụng AI nơi user giao tiếpClaude Desktop, Cursor, VS Code
MCP ClientBộ chuyển nằm trong host, nói giao thức MCPNhúng sẵn trong Claude Desktop
MCP ServerChương trình bạn viết — exposures tool/resourceops-helper.py

Client ↔ Server trao đổi qua JSON-RPC 2.0. Điểm mạnh: 1 host chạy được nhiều server cùng lúc — mỗi server phụ trách một nguồn dữ liệu (docs server, DB server, calendar server...).

sơ đồ●
# 1 host — nhiều server:
#   Claude Desktop (host)
#     ├── client ⇄ server "docs"     (đọc tài liệu công ty)
#     ├── client ⇄ server "postgres" (query DB)
#     └── client ⇄ server "calendar" (xem/lên lịch)
📝 Quiz
1. Bạn viết "MCP server" — nó đóng vai trò nào?
✅ Server là chương trình của bạn (tool/resource), được client (trong host) gọi qua JSON-RPC.

L1 · Ba trụ cột (Primitives)

Chương 5 Resources — đọc dữ liệu

Dữ liệu thụ động LLM đọc khi cần ngữ cảnh.

Resource là dữ liệu thụ động: file, dòng DB, response API. Mỗi resource có URI (file://logs/app.log, postgres://users/42). Khác tool, LLM không gọi resource — host tự nạp nội dung vào ngữ cảnh khi cần.

python · resource●
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("ops-helper")

@mcp.resource("file:///var/log/app.log")
def app_log() -> str:
    return open("/var/log/app.log").read()
Resource URI Dùng scheme chuẩn: file:// (file cục bộ), http:// (API), hoặc tự định nghĩa (config://app, postgres://...). Host hiển thị danh sách resource cho user/LLM chọn.

Chương 6 Tools — hành động

Hàm LLM gọi để thực thi — trái tim của MCP.

Tool là hàm LLM chủ động gọi để thực thi: query DB, gửi email, chạy script, restart dịch vụ. Khai báo bằng @mcp.tool() + docstring — SDK tự sinh JSON schema từ chữ ký hàm.

python · tool●
@mcp.tool()
def restart_service(name: str) -> str:
    """Khởi động lại dịch vụ `name` (vd: nginx)."""
    import subprocess
    subprocess.run(["systemctl", "restart", name], check=True)
    return f"✅ {name} restarted"
Docstring = schema SDK lấy docstring làm mô tả tool cho LLM, và type hint (name: str) làm schema tham số. Viết docstring rõ nghĩa, đặt tên tham số dễ hiểu — LLM sẽ gọi đúng lúc hơn.
📝 Quiz
1. Khác biệt cốt lõi: Resource vs Tool?
✅ Resource = ngữ cảnh (host nạp khi cần); Tool = hành động (LLM quyết định gọi).
✍️ Bài tập 2 — Khai báo tool
Viết tool get_weather(city: str) -> str trả về "nắng 32°C" cho thành phố nhập vào. Dùng decorator @mcp.tool() và có docstring.
Xem lời giải
@mcp.tool()
def get_weather(city: str) -> str:
    """Thời tiết hiện tại của `city`."""
    return f"{city}: nắng 32°C"

Chương 7 Prompts — template động

Workflow lặp — quản lý tập trung phía server.

Prompt là template quản lý ở server, thay vì hardcode trong mỗi client. Trong Claude Desktop, user gõ / → thấy danh sách prompt mà server cung cấp. Dùng cho các workflow lặp (vd /analyze-log, /weekly-report).

python · prompt●
@mcp.prompt()
def analyze_log(service: str) -> str:
    return f"Phân tích log của {service}, tìm 3 lỗi nghiêm trọng nhất."
Khi nào dùng Prompt Khi một quy trình nhiều bước xuất hiện lặp lại (phân tích log → tóm tắt → gợi ý sửa), đóng nó thành prompt server. User chỉ gõ /analyze-log nginx thay vì mô tả dài dòng mỗi lần.

L2 · Kiến trúc & giao tiếp

Chương 9 JSON-RPC 2.0

Giao thức nền — nhưng SDK che hết cho bạn.

MCP dùng JSON-RPC 2.0: mỗi message là một JSON gọn. Ba loại:

  • Request — {jsonrpc, id, method, params} → có response.
  • Notification — không có id, 1 chiều (vd server báo "đổi danh sách tool").
  • Response — {jsonrpc, id, result} hoặc error.
json-rpc · ví dụ●
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": { "name": "restart_service", "arguments": { "name": "nginx" } }
}
Bạn hiếm khi viết JSON tay SDK (FastMCP) che mọi chi tiết JSON-RPC. Bạn chỉ viết hàm Python — decorator lo phần còn lại. Hiểu giao thức để debug khi dùng Inspector (Chương 15).

Chương 10 Transport — stdio vs HTTP

Cách client-server gửi byte cho nhau.
TransportCách hoạt độngKhi nào dùng
stdioServer là process con, giao tiếp qua stdin/stdoutDev local, Claude Desktop (mặc định)
Streamable HTTPServer chạy远程 (URL), đa clientProduction, cloud, web app
Chọn đúng Bắt đầu luôn bằng stdio — đơn giản nhất, không cần port hay server riêng. Khi cần phục vụ nhiều user qua web hoặc deploy cloud → chuyển sang Streamable HTTP (chỉ đổi 1 dòng transport="http").

Chương 11 Lifecycle kết nối

Initialize → Operate → Shutdown.

Mỗi kết nối client-server đi qua 3 giai đoạn:

  1. Initialize — bắt tay: client & server trao đổi capability (server có tool? resource? sampling? client có hỗ trợ roots?).
  2. Operate — trao đổi request/notification liên tục (gọi tool, đọc resource...).
  3. Shutdown — đóng gọn gàng, giải phóng tài nguyên.
Bất đồng bộ là mặc định Server xử lý nhiều request song song → viết handler dạng async def khi có I/O (gọi DB, API). FastMCP hỗ trợ cả sync & async; sync đủ cho tool đơn giản.

Chương 12 Security & Human-in-the-loop

LLM đề nghị — code thực thi — người duyệt.
  • Control phân tách: LLM chỉ đề nghị gọi tool; code của bạn (server) thực thi — có thể validate tham số, giới hạn quyền.
  • Human approval: tool nguy hiểm (xóa DB, gửi tiền, restart production) → host xin user xác nhận trước khi chạy.
  • Sandbox: server nên giới hạn phạm vi (chỉ đọc log, không ghi hệ thống; chỉ truy cập 1 thư mục).
  • Không tin input: mọi dữ liệu server fetch (web, PDF) coi như đã bị ô nhiễm — đánh dấu "data, không phải chỉ thị" để tránh indirect injection.
Nguyên tắc an toàn #1 Không bao giờ để LLM tự ý chạy tool không hoàn tác được. Mọi tool "gửi / xóa / sửa" phải qua xác nhận người. Server cũng nên chạy với quyền tối thiểu (không root, không admin).
📝 Quiz
1. Tool delete_record(id) — xử lý an toàn thế nào?
✅ Tool không hoàn tác được → phải qua human approval. Control phân tách: LLM đề nghị, người duyệt.

Chương 13 Build MCP Server Python

Mini-project: đọc log + restart dịch vụ.

Đây là server hoàn chỉnh từ dàn ý của khóa — 1 Resource (đọc log) + 1 Tool (restart dịch vụ). Lưu thành ops_helper.py.

python · ops_helper.py●
from mcp.server.fastmcp import FastMCP
import subprocess

mcp = FastMCP("ops-helper")

@mcp.resource("file:///var/log/app.log")
def app_log() -> str:
    """Log ứng dụng mới nhất."""
    return open("/var/log/app.log").read()

@mcp.tool()
def restart_service(name: str) -> str:
    """Restart dịch vụ `name` (vd nginx, postgres)."""
    subprocess.run(["sudo", "systemctl", "restart", name], check=True)
    return f"restarted {name}"

if __name__ == "__main__":
    mcp.run(transport="stdio")
✍️ Bài tập 3 — Thêm resource
Thêm resource URI config://app trả nội dung file app.yaml (dùng decorator @mcp.resource(...)).
Xem lời giải
@mcp.resource("config://app")
def app_config() -> str:
    return open("app.yaml").read()

Chương 15 Debug bằng MCP Inspector

Khi tool không hiện — đây là cứu cánh.
bash●
npx @modelcontextprotocol/inspector python ops_helper.py

Inspector mở UI web để: gọi thử tool/resource, xem JSON-RPC traffic, bắt lỗi schema. Bắt buộc khi tool không hiện trong Claude.

Lỗi thường gặp & cách xử lý
  • Tool không hiện trong Claude → schema sai, hoặc exception trong handler → xem log Claude (mcp.log).
  • Server crash ngay sau khởi động → import lỗi / thiếu thư viện → chạy python ops_helper.py trực tiếp để xem traceback.
  • Đường dẫn sai → Claude chạy server từ thư mục khác; dùng đường dẫn tuyệt đối trong config.
  • Python khác → Claude dùng Python hệ thống, không thấy thư viện venv → chỉ rõ path venv trong command.

Chương 16 Dự án & deploy

Từ mini-project lên production.

Capstone — server tra cứu nội bộ (RAG-lite):

  1. Resource: đọc 20–50 tài liệu PDF/Markdown công ty.
  2. Tool: search_docs(query) — semantic search qua vector DB (FAISS/Qdrant).
  3. Prompt: /ask-doc — template "trả lời dựa tài liệu, trích nguồn".
  4. Transport: stdio cho Claude Desktop; Streamable HTTP (FastAPI + Docker) cho web app.
Mở rộng 1 host chạy được nhiều server cùng lúc: docs + postgres + calendar. LLM có thể phối hợp tool giữa các server (vd "tìm trong docs rồi thêm sự kiện vào calendar"). Đó là sức mạnh thực sự của MCP.
✍️ Bài tập 5 — Chạy server
Viết dòng cuối file để chạy server ở transport stdio: gọi mcp.run(transport="stdio").
Xem lời giải
if __name__ == "__main__":
    mcp.run(transport="stdio")
