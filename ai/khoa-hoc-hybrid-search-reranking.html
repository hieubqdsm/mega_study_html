Hybrid Search & Re-ranking — nâng Recall RAG > 90%

16 chương theo 4 cấp độ. Kết hợp Sparse (BM25) + Dense (embedding) + Cross-encoder để đẩy Recall@5 của RAG từ ~70% lên >90%. Khóa thực hành hướng dẫn dựng pipeline BM25 ⊕ Dense → RRF → rerank, đo cải thiện thật. Mỗi chương có code, bài tập tự chấm, quiz, flashcard.

L0 · Nền tảng

Chương 1 Vì sao chỉ Dense Search chưa đủ

Embedding giỏi ngữ nghĩa — nhưng bỏ sót từ khóa chính xác.

Dense (embedding) giỏi khớp ngữ nghĩa nhưng bỏ sót từ khóa chính xác (tên riêng, mã số, thuật ngữ kỹ thuật). Query "Thông tư 08" — Dense có thể trả tài liệu về "quy định ngân hàng" (liên quan ngữ nghĩa) mà lỡ tài liệu thực sự chứa cụm "Thông tư 08". BM25 lại bắt chính xác. Hybrid = cộng sức.

Bài học thực tế Hệ thống RAG production hiếm khi chỉ dùng Dense. Hybrid + re-ranking là chuẩn de-facto ở Qdrant, Weaviate, Elasticsearch, Pinecone — đều hỗ trợ native. Học được cái này = nâng chất lượng RAG rõ rệt mà không đổi model.

Chương 2 Sparse vs Dense Retrieval

Hai họ vector — hai thế mạnh khác nhau.
  • Sparse vector: nhiều chiều (kích thước vocabulary), mỗi chiều ứng với 1 từ, hầu hết = 0. Ví dụ: BM25, TF-IDF. Mô hình: đếm/trọng số từ.
  • Dense vector: vài trăm chiều (768/1536), tất cả mang thông tin. Sinh bởi embedding model (Sentence-BERT, BGE, OpenAI). Nắm ngữ nghĩa.
Vì sao "sparse" Vector sparse dài hàng nghìn/trăm nghìn chiều nhưng chỉ vài giá trị ≠ 0 (từ nào xuất hiện). Chiếc "nén tự nhiên" — phù hợp khớp từ khóa. Dense ngược lại: ngắn nhưng đặc — phù hợp khớp ý.

Chương 3 Hybrid Search là gì

Sparse + Dense song song → fusion → (re-rank).

Hybrid Search = chạy cả Sparse & Dense song song, rồi fusion (gộp) kết quả. Thường thêm re-ranking bằng cross-encoder cho top cuối.

sơ đồ●
#     Query
#     ┌────┴────┐
#   Sparse    Dense           ← retrieval song song
#  (BM25)   (embedding)
#   top20    top20
#     └────┬────┘
#       Fusion (RRF)           ← gộp theo thứ hạng
#       top15
#         │
#   Cross-encoder rerank       ← xếp lại chính xác
#       top5 → prompt LLM

Chương 8 Đo Recall@k

Chỉ số quyết định — không đo = không cải thiện được.
công thức●
# Recall@k = (số tài liệu ĐÚNG nằm trong top-k) / (tổng tài liệu ĐÚNG cho query)
def recall_at_k(retrieved_ids, relevant_ids, k=5):
    topk = set(retrieved_ids[:k])
    return len(topk & set(relevant_ids)) / len(relevant_ids)
Golden set là yêu cầu Cần golden set: các câu hỏi có sẵn danh sách tài liệu đúng (do người gán). Không có golden set = không thể nói "hybrid tốt hơn" một cách khách quan. Đây là đầu việc tốn công nhưng bắt buộc.
📝 Quiz
1. Recall@5 = 0.8 nghĩa là gì?
✅ Recall@k đo "tìm được bao nhiêu phần trăm cái ĐÚNG" — khác Precision (đo "trong kết quả bao nhiêu cái đúng").
L2 · Fusion & Re-ranking

Chương 9 Vì sao KHÔNG trộn điểm trực tiếp

Thang điểm BM25 & cosine khác nhau.

Điểm BM25 (0–vài chục) và cosine (0–1) thang khác nhau → trộn trực tiếp 0.5*bm25 + 0.5*dense vô nghĩa: BM25 luôn áp đảo. Cần fusion theo thứ hạng (rank), không theo điểm.

Lỗi phổ biến #1 Trộn alpha*bm25_score + (1-alpha)*dense_score. Trông "khoa học" nhưng sai, vì thang điểm không so sánh được. Dùng RRF (chương 10) hoặc normalize trước khi trộn.

Chương 10 Reciprocal Rank Fusion (RRF)

Fusion theo thứ hạng — đơn giản & hiệu quả.

RRF chấm mỗi doc theo thứ hạng nó xuất hiện trong các list, không cần normalize điểm:

công thức RRF●
# score(doc) = Σ  1 / (k + rank_i(doc))     với k thường = 60
# rank_i(doc): thứ hạng của doc trong list i (bắt đầu từ 1)
# doc không có trong list i → không cộng
python · RRF●
def rrf(lists, k=60):
    scores = {}
    for lst in lists:
        for rank, doc in enumerate(lst, 1):
            scores[doc] = scores.get(doc, 0) + 1/(k + rank)
    return sorted(scores, key=scores.get, reverse=True)
k=60 từ đâu k điều chỉnh "độ ưu tiên top đầu". k lớn → ưu tiên ít hơn (cân bằng). k nhỏ → top đầu được ưu tiên mạnh. 60 là giá trị gốc từ paper, hoạt động tốt trong thực tế — hiếm khi cần đổi.

Chương 12 Re-ranking với bge-reranker

Cross-encoder mạnh, đa ngữ cho tiếng Việt.

from FlagEmbedding import FlagReranker

reranker = FlagReranker("BAAI/bge-reranker-base", use_fp16=True)
# bge-reranker-m3 cho đa ngữ (tiếng Việt tốt hơn)

pairs = [[query, corpus[i]] for i in candidates]

Chương 13 Pipeline Hybrid đầy đủ

Ráp cả 3 giai đoạn thành 1 hàm.
python · hybrid_search●
def hybrid_search(query, top_k=5, top_n=20, k=60):
    # 1) Sparse + Dense song song
    sparse = bm25_top(query, n=top_n)        # list id từ BM25
    dense  = dense_top(query, n=top_n)       # list id từ Qdrant
    # 2) Fusion theo thứ hạng
    fused = rrf([sparse, dense], k=k)[:15]
    # 3) Re-rank bằng cross-encoder
    pairs = [[query, corpus[i]] for i in fused]
    scores = reranker.compute_score(pairs)
    ranked = sorted(zip(scores, fused), reverse=True)
    return [i for _, i in ranked][:top_k]

Chương 14 Đánh giá: Dense vs Hybrid+Rerank

Đo bằng số — không tin lời.
Cấu hìnhRecall@5Latency
Dense only~70%Nhanh nhất

Đánh đổi Rerank thêm ~20–50ms/query (top-15 qua cross-encoder). Với RAG user-facing, độ trễ này đáng đổi lấy +15-25% recall. Nếu query volume cực cao → cache hoặc chỉ rerank khi query "khó".

Chương 15 Mẹo & tối ưu

Vặn từng nút khi chưa đạt recall.
  • alpha fusion — RRF thuần không cần; nếu cần thiên lệch sparse/dense, dùng weighted RRF.
  • k RRF — 60 mặc định; giảm (vd 30) nếu muốn ưu tiên top đầu.
  • top-n mỗi giai đoạn — quá ít = mất recall; quá nhiều = chậm reranker. 20 là điểmsweet.
  • batch reranker — compute_score(list) 1 lần, không lặp từng cặp.
  • cache embedding — doc embedding tính 1 lần & lưu; chỉ query embedding tính mỗi lần.
  • reranker đa ngữ — tiếng Việt: bge-reranker-m3 > base.
Đừng tối ưu sớm Bắt đầu với default (RRF k=60, top-20 mỗi bên, rerank top-15→5). Đo recall. Chỉ vặn núm khi chưa đạt mục tiêu — từng cái một, đo lại mỗi lần.

Chương 16 Dự án: RAG tiếng Việt

Ráp mọi thứ — đo trên dữ liệu thật.
  1. Dữ liệu: 1000 chunks tài liệu tiếng Việt (luật/văn bản công ty). Gán golden 20 câu (mỗi câu chỉ rõ tài liệu đúng).
  2. Index: Qdrant hybrid (dense BGE-m3 + sparse). Chunk tiếng Việt tokenize bằng underthesea.
  3. Pipeline: BM25 ⊕ Dense → RRF → bge-reranker-m3 → top-5.
  4. Đo: Recall@5 của Dense only vs Hybrid+rerank trên golden 20 câu.
  5. Tích hợp RAG: dùng top-5 làm context trong LangChain / LlamaIndex pipeline.
