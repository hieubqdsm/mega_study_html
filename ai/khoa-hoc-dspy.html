16 chương theo 4 cấp độ. DSPy (Stanford NLP) thay "gõ prompt bằng text" bằng khai báo code (Signature → Module), rồi để framework tự tìm prompt/few-shot tối ưu bằng ML (Teleprompter). Đổi tư duy từ "Kỹ sư gõ text" sang "Kỹ sư lập trình AI". Mỗi chương có code, bài tập tự chấm, quiz, flashcard.

L0 · Nhập môn

Chương 1 DSPy là gì

Từ "gõ prompt" sang "lập trình AI".

DSPy (Declarative Self-improving Language Programs, python) là framework của Stanford NLP (2023). Triết lý: thay vì viết prompt bằng text & thử-nhầm nhiều lần, khai báo luồng chương trình bằng code, rồi để framework tự sinh & tối ưu prompt (instruction + few-shot) bằng machine learning.

Manual PromptingDSPy
Viết promptTay, thử-nhầmKhai báo Signature, code tự sinh
Few-shot examplesChọn tay, cố địnhTự sinh + chắt lọc (Bootstrap)
Đổi modelViết lại promptCompile lại, prompt tự thích ứng
Version controlCopy-paste textGit như code thường
Thay đổi tư duy Bạn ngừng lo "dùng từ nào cho LLM hiểu". Bạn lo logic (Input gì → Output gì → qua mấy bước); DSPy lo wordsmithing. Giống như bạn viết Python thay vì viết assembly.
📝 Quiz nhanh
1. DSPy khác prompt engineering truyền thống ở điểm cốt lõi nào?
✅ DSPy = khai báo (Signature/Module) + tối ưu tự động (Teleprompter). Bạn lo logic, DSPy lo prompt.

Chương 2 Sự cạn kiệt của prompt truyền thống

Vì sao "tinh chỉnh prompt bằng tay" là ngõ cụt ở quy mô lớn.

Prompt text dài có 4 vấn đề: khó bảo trì (sửa 1 câu có thể hỏng cả luồng), phụ thuộc cảm tính ("thêm từ 'chú ý' có giúp không?"), không tái dùng giữa model (prompt tốt cho GPT-4 có thể tệ với Llama), và khó tối ưu (không có "gradient" để biết hướng sửa).

Separation of concerns DSPy mượn nguyên lý kỹ thuật phần mềm: tách luồng chương trình (program flow — cái bạn viết bằng code) khỏi tham số (prompt strings — cái DSPy tối ưu). Giống model vs weights trong ML: bạn thiết kế kiến trúc, optimization đi tìm weights.

Chương 3 Cài đặt & config LM

Một LM toàn cục cho mọi module.
bash + python●
pip install dspy
python · config LM●
import dspy

lm = dspy.LM("openai/gpt-4o-mini", api_key="sk-...")
dspy.configure(lm=lm)        # đặt làm LM mặc định toàn cục

# Provider khác:
#   dspy.LM("anthropic/claude-3-5-sonnet")
#   dspy.LM("ollama/llama3")              # local, miễn phí
Một LM cho tất cả dspy.configure(lm=...) đặt LM mặc định. Mọi module sau dùng chung — không cần truyền client= từng nơi. Muốn override riêng: with dspy.context(lm=other_lm): ....
✍️ Bài tập 1 — Config LM
Tạo lm = dspy.LM("openai/gpt-4o-mini") rồi đặt làm LM mặc định bằng dspy.configure(lm=lm).

Chương 4 Pipeline đầu tiên (Predict)

Vài dòng — không viết 1 dòng text prompt.
python●
classify = dspy.Predict("sentence -> sentiment")
r = classify(sentence="Phim này hay quá!")
print(r.sentiment)   # "tích cực"

Signature "sentence -> sentiment" đủ để DSPy tự sinh prompt hoàn chỉnh, gọi LLM, parse kết quả vào r.sentiment. Không cần f"...", không cần parse text.

"->" là cú pháp Signature DSPy hiểu "A -> B" là: nhận input A, trả output B. Nhiều input/output: "context, question -> answer".
L1 · Primitives

Chương 5 Signature — Input/Output

Hợp đồng giữa bạn và LLM — khai báo bằng code.

Signature khai báo Input → Output của một bước. Hai dạng:

Dạng chuỗi — gọn, cho việc nhanh

python●
qa = dspy.Predict("question -> answer")

Dạng class (typed) — đầy đủ, có docstring & mô tả trường

python · typed signature●
class QA(dspy.Signature):
    """Trả lời câu hỏi sự thật, ngắn gọn."""
    question = dspy.InputField()
    answer = dspy.OutputField(desc="tối đa 1 câu, chính xác")
Docstring = instruction Docstring của class trở thành instruction (chỉ dẫn) trong prompt. desc= của field mô tả định dạng mong muốn. DSPy dùng cả hai để sinh prompt đầy đủ — bạn không phải wordsmithing.
📝 Quiz
1. Trong class QA(dspy.Signature), docstring đóng vai trò gì?
✅ Docstring → instruction. Cùng với desc của field, DSPy dùng để tự sinh prompt đầy đủ.

Chương 6 Module Predict

Viên gạch nền — gọi LLM 1 lần theo signature.

Predict là module đơn giản nhất: nhận signature, gọi LLM đúng 1 lần, trả output. Mọi module khác (ChainOfThought, ReAct) đều mở rộng từ Predict.

python●
summarize = dspy.Predict("text -> summary")
print(summarize(text="Bài viết dài...").summary)
Dùng khi nào Bài toán "trực tiếp" — không cần suy luận nhiều bước (phân loại cảm xúc, trích thực thể, tóm tắt ngắn). Cần reasoning → dùng ChainOfThought (chương 7).

Chương 7 Module ChainOfThought

Tự thêm bước reasoning — tăng chất lượng bài toán khó.

ChainOfThought thêm trường reasoning trước output. DSPy tự chèn bước suy luận (tương đương "Let's think step by step") — LLM "nghĩ" rồi mới trả lời.

python●
solve = dspy.ChainOfThought("question -> answer")
r = solve(question="Nếu 3 máy in in 3 trang trong 3 phút, 100 máy in in 100 trang mất bao lâu?")
print(r.reasoning)   # "Mỗi máy in 1 trang / 3 phút..."
print(r.answer)      # "3 phút"
Đánh đổi ChainOfThought dùng nhiều token hơn Predict (sinh thêm reasoning) và chậm hơn. Dùng cho bài toán cần suy luận (toán, logic, QA phức tạp) — với bài toán trivial, Predict đủ.
✍️ Bài tập 2 — Tạo module ChainOfThought
Tạo module solve = dspy.ChainOfThought("question -> answer").
Xem lời giải
solve = dspy.ChainOfThought("question -> answer")

Chương 8 Module ReAct & compose

Dùng tool & ghép module thành pipeline.

ReAct = module dùng tool: LLM Reason → Act (gọi tool) → Observe → lặp. Cần truyền danh sách tool.

python●
agent = dspy.ReAct("question -> answer", tools=[search, calculator])
print(agent(question="GDP Việt Nam 2023 nhân 2?").answer)
Compose — sức mạnh thật sự Module là "hàm" — bạn có thể lồng nhau thành pipeline phức tạp (giống function composition). Ví dụ: Retrieve → ChainOfThought → Predict(format). Đây là cách DSPy scale từ 1 bước lên pipeline nhiều bước mà vẫn declarative.
L2 · Tối ưu hóa (Teleprompter)

Chương 9 Teleprompter là gì

"Trình biên dịch prompt" — tối ưu tự động.

Teleprompter nhận (module gốc + trainset + metric) → trả về module đã tối ưu: prompt/few-shot được sinh & chọn tự động. Quá trình gọi là compile — giống compile code (code → bytecode tối ưu).

sơ đồ compile●
# student: module gốc (chưa tối ưu)
# trainset: vài chục example (input + label mong muốn)
# metric: hàm chấm "đúng/sai"
compiled = teleprompter.compile(student=student, trainset=trainset)
# → compiled là module ĐÃ tối ưu (prompt tốt hơn, có few-shot)
📝 Quiz
1. Teleprompter cần gì để compile một module?
✅ Ba thứ: student (module), trainset (ví dụ), metric (đánh giá) — để biết cái nào "tốt" mà giữ lại làm few-shot.

Chương 10 BootstrapFewShot

Tự sinh few-shot từ ví dụ thành công.

BootstrapFewShot chạy module trên trainset, giữ lại các ví dụ thành công (đạt metric) làm few-shot demos. Tự động chọn ví dụ tốt — không cần đoán "ví dụ nào minh hoạ rõ".

python●
from dspy.teleprompt import BootstrapFewShot

tele = BootstrapFewShot(metric=my_metric, max_bootstrapped_demos=4)
compiled = tele.compile(student=classify, trainset=trainset)
max_bootstrapped_demos Số few-shot tối đa được sinh. Vài demo (3–8) thường đủ. Nhiều quá = prompt dài + tốn token + đôi khi giảm chất lượng (distract).
✍️ Bài tập 3 — Compile module
Gọi compiled = tele.compile(student=classify, trainset=trainset).
Xem lời giải
compiled = tele.compile(student=classify, trainset=trainset)

Chương 11 MIPRO / COPRO

Tối ưu cả instruction — không chỉ few-shot.
TeleprompterTối ưu gìChi phí
BootstrapFewShotFew-shot demosRẻ — khởi đầu tốt
COPROInstruction (prefix)Trung bình
MIPROCả instruction + few-shotĐắt (Bayesian search) — mạnh nhất
Thứ tự thực tế Bắt đầu với BootstrapFewShot (rẻ, đã tốt). Chưa đủ → COPRO. Cần vắt kiệt → MIPRO. Mỗi bước đo trên eval riêng để biết có thực sự cải thiện.

Chương 12 Metrics (hàm đánh giá)

"Metric sai = tối ưu sai hướng."

Metric nhận (example, pred, trace) → trả số/bool. Có thể exact-match, hoặc dùng LLM-as-judge cho output tự do.

python · exact match●
def exact_match(example, pred, trace=None):
    return example.answer.strip().lower() == pred.answer.strip().lower()
python · LLM-as-judge (dspy.Signature)●
class Judge(dspy.Signature):
    """Chấm câu trả lời 1-5 theo độ chính xác."""
    question = dspy.InputField()
    answer = dspy.InputField()
    score  = dspy.OutputField(desc="số 1 đến 5")
Metric là thứ quan trọng nhất Teleprompter tối ưu cho metric của bạn. Metric hẹp/sai → module "tốt" trên paper nhưng tệ thực tế. Dành thời gian thiết kế metric kỹ — đáng giá hơn tinh chỉnh bất cứ tham số nào.

Chương 13 Inspect — xem prompt DSPy sinh

Mở "hộp đen" — biết DSPy thực sự gửi gì.

Sau khi gọi module, dspy.inspect_history(n=1) in prompt thật sự gửi cho LLM (kèm few-shot DSPy đã chèn). Quan trọng để hiểu & debug.

python●
classify(sentence="Phim dở")
dspy.inspect_history(n=1)
# In ra prompt đầy đủ:
#   system: "Given a sentence, classify sentiment..."  ← DSPy sinh
#   few-shot: 4 ví dụ                                ← Bootstrap chèn
#   user: "Phim dở"

Chương 14 So sánh manual vs DSPy

Đo bằng số — không tin lời.
python · Evaluate●
from dspy import Evaluate
eval = Evaluate(devset=testset, metric=exact_match, num_threads=4)
print(eval(classify))    # baseline (không compile)
print(eval(compiled))    # đã compile — thường cao hơn
Manual promptDSPy baselineDSPy compiled
Accuracy (điển hình)~70%~72%~80%+
Nỗ lựcThử-nhầm tay01 lần compile
Tái lậpKhóCaoCao
Kết quả thực tế Nghiên cứu DSPy cho thấy compiled thường nhỉnh hơn baseline vài %, và ổn định hơn — không phụ thuộc "may mắn" chọn prompt tay. Đổi model? Compile lại, prompt tự thích ứng.

Chương 15 Mẹo & lỗi thường gặp

Tránh những cái bẫy phổ biến.
  • Metric phải xác đáng — metric sai = tối ưu sai hướng. Dành thời gian thiết kế metric kỹ.
  • Trainset đủ đa dạng — vài chục example đa dạng tốt hơn rất nhiều ví dụ giống nhau.
  • Compile tốn token — chạy module nhiều lần trên trainset. Giới hạn max_bootstrapped_demos & max_labeled_demos.
  • Overfit trainset — giữ holdout eval riêng; đừng compile trên chính tập eval.
  • Đổi model → compile lại — prompt tối ưu khác nhau giữa GPT-4o-mini và Claude; prompt không "chuyển giao" nguyên vẹn.
  • Output không parse được → thêm desc= rõ ràng cho OutputField (vd "chỉ trả JSON").
Bẫy "compile mãi không xong" MIPRO có thể chạy rất lâu & tốn nhiều token. Bắt đầu bằng BootstrapFewShot, đo eval, rồi mới quyết định có cần MIPRO không. Đừng bật MIPRO ngay từ đầu.

Chương 16 Dự án: classification/QA pipeline

End-to-end — ráp tất cả lại.

Capstone — pipeline phân loại/QA đầy đủ:

  1. Dữ liệu: dataset (vd review → sentiment, hoặc FAQ QA). Chia train/eval.
  2. Signature typed: class Sentiment(dspy.Signature) với InputField/OutputField + docstring.
  3. Module: dspy.ChainOfThought(Sentiment) (nếu cần reasoning).
  4. Metric: exact_match hoặc LLM-as-judge.
  5. Compile: BootstrapFewShot(metric=...).compile(...).
  6. Đánh giá: Evaluate so sánh baseline vs compiled.
  7. Inspect: dspy.inspect_history() xem prompt DSPy sinh.

Tạo module clf = dspy.Predict("review -> sentiment") để phân loại cảm xúc review.
Xem lời giải
