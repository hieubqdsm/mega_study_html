Gợi ý

Nếu bạn không quan tâm đến chi tiết kỹ thuật, một nguyên tắc kinh nghiệm tốt để chọn định dạng đầu ra cho dự án của bạn là:

Dùng OpenEXR

nếu bạn định thực hiện compositing hoặc color grading trên các hình ảnh này.

Dùng PNG

nếu bạn định xuất để xem trên màn hình hoặc encode sang nhiều định dạng video.

Dùng JPEG

cho xuất trên màn hình trong trường hợp kích thước file là điều cần cân nhắc và mất chất lượng một chút là chấp nhận được.

Tất cả các định dạng này đều hỗ trợ nén, điều này có thể quan trọng khi render ra các animation.

Gợi ý

Độ sâu bit của các định dạng hình ảnh biểu diễn số mức tông màu trên mỗi kênh như sau:

12:

Mở Hình Ảnh¶

Relative Path

Đặt đường dẫn file thành tương đối so với blend-file đang mở.

Xem Đường dẫn Tương đối.

Detect Sequences

Tự động tìm các chuỗi hình ảnh (image sequence) trong các hình ảnh được chọn (dựa trên tên file). Tắt tùy chọn này khi bạn muốn lấy các hình ảnh đơn lẻ vốn là một phần của chuỗi. Xem Mở một Chuỗi Hình Ảnh để biết thêm thông tin.

Detect UDIMs

Tự động tìm các tile UDIM trong thư mục của hình ảnh được chọn; nếu tìm thấy kết quả khớp, chúng được tải vào Blender dưới dạng UDIM. Tính năng này hoạt động bằng cách phát hiện xem tên file có một .xxxx (số bốn chữ số) trước phần mở rộng file hay không.

Mở một Chuỗi Hình Ảnh¶

Để tải chuỗi hình ảnh ở bất kỳ định dạng file hình ảnh được hỗ trợ nào, tên file của các hình ảnh phải chứa một chữ số để chỉ thứ tự frame (ví dụ *-0001.jpg, *-0002.jpg, *-0003.jpg, v.v., của bất kỳ định dạng hình ảnh nào), biểu thị frame.

Chuỗi có thể được mở bằng cách chọn các hình ảnh với bất kỳ phương pháp nào dưới đây, rồi xác nhận bằng nút Open Image hoặc Return.

Range

Điều hướng vào thư mục và LMB nhấp rồi kéo qua một khoảng tên để làm nổi bật nhiều file. Bạn có thể page down và tiếp tục nhấp-kéo bằng Shift-LMB để thêm nhiều file vào phần chọn.

Batch

Nhấp Shift-LMB vào các hình tĩnh không liên quan được chọn để xử lý theo lô; mỗi hình ảnh sẽ là một frame, theo thứ tự sắp xếp, và có thể là hỗn hợp nhiều kiểu file (jpg, png, exr, v.v.).

All

Nhấn A để chọn/bỏ chọn tất cả các file trong thư mục.

Lưu Các Hình Ảnh Đã Chỉnh Sửa¶

Các hình ảnh được chỉnh sửa bên trong Blender, chẳng hạn texture đã vẽ, hình ảnh được tạo, hoặc kết quả compositor, được lưu trữ tách biệt với chính blend-file.

Khi thoát Blender hoặc lưu blend-file, các hình ảnh đã chỉnh sửa có thể cần được lưu thủ công tùy thuộc vào hành vi được cấu hình trong Save Modified Images.

Các hình ảnh chưa lưu được đánh dấu bằng dấu sao (*) trong Image Editor và các thành phần giao diện khác.

Lưu Blend-File¶

Khi lưu blend-file, Blender có thể:

  • Hỏi xem các hình ảnh đã chỉnh sửa có nên được lưu hay không.

  • Tự động lưu các hình ảnh đã chỉnh sửa.

  • Bỏ qua các hình ảnh đã chỉnh sửa.

Hành vi này được điều khiển bởi tùy chỉnh Save Modified Images.

Thoát Blender¶

Khi thoát Blender, các hình ảnh đã chỉnh sửa nhưng chưa lưu có thể kích hoạt hộp thoại xác nhận.

Nếu các hình ảnh đã chỉnh sửa bị bỏ mà không lưu, mọi thay đổi hình ảnh chưa lưu sẽ bị mất vĩnh viễn.

Mẹo

Để lưu hình ảnh thủ công, hãy dùng:

  • Save

  • Save As

  • Save All Images

Cảnh báo

Các hình ảnh Render Result và kết quả node Compositor Viewer là tạm thời và không được tự động lưu vào đĩa khi lưu blend-file hay thoát Blender.

Những kết quả này phải được lưu thủ công nếu muốn giữ lại.

Không lưu những hình ảnh này trước khi render lại, tải file mới, hoặc thoát Blender sẽ khiến dữ liệu hình ảnh bị mất.

Cài Đặt Hình Ảnh¶

File Format

Chọn định dạng file hình ảnh để lưu vào. Tùy vào định dạng được dùng, các tùy chọn khác như kênh màu, độ sâu bit và mức nén sẽ khả dụng.

Color

Định dạng màu để lưu hình ảnh hoặc video. Cài đặt này được một số định dạng dùng để tối ưu lượng dữ liệu được ghi vào file. Lưu ý, RGBA không khả dụng cho mọi định dạng hình ảnh, hãy xem danh sách phía trên để biết chi tiết.

BW:

Lưu hình ảnh dùng màu thang độ xám.

RGB:

Lưu các kênh màu đỏ, lục và lam

RGBA:

Lưu các kênh màu đỏ, lục, lam và alpha.

Color Depth

Định nghĩa độ sâu bit trên mỗi kênh màu, xác định có bao nhiêu giá trị màu có thể được biểu diễn.

Độ sâu bit cao hơn giúp giảm hiện tượng banding màu và cải thiện độ chính xác nhưng cũng làm tăng kích thước file và mức sử dụng bộ nhớ. Lưu ý, không phải mọi định dạng file đều hỗ trợ mọi độ sâu màu.

8:

Phổ biến nhất cho đồ họa trên màn hình, web và video tiêu chuẩn. Phù hợp cho mục đích sử dụng chung.

10, 12, 16:

Được dùng bởi các định dạng tập trung vào nhiếp ảnh và điện ảnh kỹ thuật số (ví dụ DPX, JPEG 2000). Cung cấp dải tông màu và chi tiết màu nhiều hơn 8-bit.

32:

Số thực dấu phẩy động 32-bit trên mỗi kênh. Cung cấp độ chính xác và dải động cao nhất. Độ sâu màu cao nhất có thể, chủ yếu được dùng với OpenEXR cho các quy trình hiệu ứng hình ảnh và compositing.

Float (Half):

Số thực dấu phẩy động 16-bit trên mỗi kênh. Cung cấp dải động cao với mức sử dụng bộ nhớ và lưu trữ thấp hơn. Chỉ được hỗ trợ cho file OpenEXR.

Float (Full):

Số thực dấu phẩy động 32-bit trên mỗi kênh. Cung cấp độ chính xác và dải động cao nhất. Chỉ được hỗ trợ cho file OpenEXR.

Ghi chú

Nội bộ, Blender chỉ hoạt động ở 8-bit hoặc 32-bit.

Các hình ảnh có độ chính xác cao hơn 8-bit (ví dụ 10-bit, 12-bit, 16-bit) được chuyển sang float 32-bit khi được tải vào Blender.

Compression

Được dùng để giảm kích thước file hình ảnh. Cách thực hiện có thể khác nhau tùy thuộc vào định dạng file và các cài đặt được dùng.

Quality

Điều khiển mức nén có mất dữ liệu (lossy) áp dụng lên hình ảnh, biểu diễn dưới dạng phần trăm. Nén lossy giảm kích thước file bằng cách loại bỏ một phần dữ liệu hình ảnh, có thể dẫn đến mất chi tiết.

  • 0%: Nén tối đa, tạo ra kích thước file nhỏ nhất nhưng mất chất lượng rõ rệt nhất.

  • 100%: Không nén, giữ nguyên toàn bộ chất lượng hình ảnh với cái giá là kích thước file lớn hơn.

Save As Render

Lưu hình ảnh kèm quản lý màu của render. Đối với các định dạng hình ảnh để hiển thị như PNG, áp dụng view và display transform. Đối với các định dạng hình ảnh trung gian như OpenEXR, dùng color space đầu ra render mặc định.

Copy

Xác định data-block sẽ tham chiếu đến file mới được tạo hay tham chiếu giữ nguyên không đổi, duy trì với file gốc.

Color Space

Để chỉ định color space của file nguồn.

Danh sách color space phụ thuộc vào OCIO config đang hoạt động. Các color space được hỗ trợ mặc định được mô tả chi tiết tại đây: Default OpenColorIO Configuration

Ghi chú

Lưu ý, các kiểu hình ảnh Cineon, DPX, OpenEXR và Radiance HDR mặc định được lưu trong color space tuyến tính (linear).

Chi Tiết Định Dạng¶

Cineon & DPX¶

Cineon là tiêu chuẩn quét phim của Kodak, 10 bit trên mỗi kênh và theo thang logarit. DPX được dẫn xuất từ Cineon như là tiêu chuẩn công nghiệp ANSI/SMPTE. DPX hỗ trợ màu/kênh 16-bit, cả tuyến tính lẫn logarit. DPX hiện là tiêu chuẩn được áp dụng rộng rãi trong ngành phần cứng/phần mềm điện ảnh.

DPX cũng như Cineon chỉ lưu trữ và chuyển đổi dải giá trị màu "khả kiến" nằm giữa 0.0 và 1.0 (là kết quả của render hoặc composite).

OpenEXR¶

OpenEXR của ILM đã trở thành tiêu chuẩn của ngành phần mềm cho file hình ảnh HDR, đặc biệt nhờ cấu trúc linh hoạt và có thể mở rộng của nó.

Một file OpenEXR có thể lưu nhiều layer và pass. Điều này có nghĩa là các hình ảnh OpenEXR có thể được tải vào Compositor mà vẫn giữ nguyên các render layer và pass.

Ghi chú

Khi mở các hình ảnh OpenEXR, Blender sẽ tự động đặt Color Space nếu nó được phát hiện là Linear CIE-XYZ E hoặc ACES2065-1.

Các Tùy Chọn Đầu Ra¶

Các tùy chọn khả dụng cho đầu ra render OpenEXR là:

Color Depth

Giá trị số mũ (cơ số hai) cho việc có bao nhiêu màu có thể được biểu diễn trong một kênh màu duy nhất. Độ sâu bit cao hơn cho phép nhiều màu khả dụng hơn, giảm banding và tăng độ chính xác. Tuy nhiên độ sâu bit cao hơn sẽ làm tăng mức sử dụng bộ nhớ theo cấp số nhân.

Float (Half):

Lưu hình ảnh theo kiểu 16 bit tùy chỉnh trên mỗi kênh ở định dạng dấu phẩy động. Điều này làm giảm "độ sâu bit" thực tế xuống 10-bit, với 5-bit cho giá trị số mũ và 1-bit cho dấu.

Float (Full):

Lưu hình ảnh dùng 32 bit trên mỗi kênh ở định dạng dấu phẩy động.

Codec

Kiểu nén dùng để encode file EXR.

None:

Tắt toàn bộ nén để có thời gian encode nhanh nhất nhưng tạo ra kích thước file lớn hơn.

ZIP:

Nén lossless dùng Zlib trên các khối hình ảnh 16 hàng.

PIZ:

Nén wavelet lossless, hiệu quả cho các hình ảnh nhiễu/nhiều hạt (grainy).

DWAA (lossy):

Nén lossy kiểu JPEG trên các khối hình ảnh 32 hàng.

DWAB (lossy):

Nén lossy kiểu JPEG trên các khối hình ảnh 256 hàng.

HTJ2K:

Nén lossless dựa trên encoding JPEG 2000 thông lượng cao. Nó tạo ra file nhỏ hơn, nhưng còn mới và chưa được phần mềm khác hỗ trợ rộng rãi.

ZIPS:

Nén lossless dùng Zlib, mỗi hàng hình ảnh được nén riêng biệt

RLE:

Nén mã hóa độ dài chạy (run length encoding) lossless, hoạt động tốt khi các hàng hình ảnh có cùng giá trị.

Pxr24 (lossy):

Chuyển float 32-bit sang 24 bit rồi dùng nén deflate. Pxr24 là lossless đối với dữ liệu half và số nguyên 32-bit, và hơi lossy đối với dữ liệu float 32-bit.

B44 (lossy):

Nén lossy cho hình ảnh float 16 bit, với tỉ lệ cố định 2.3:1. B44 nén đồng đều bất kể nội dung hình ảnh.

B44A (lossy):

Nén lossy cho hình ảnh float 16 bit, với tỉ lệ cố định 2.3:1, đồng thời các vùng màu phẳng được nén thêm nữa, chẳng hạn các kênh alpha.

Quality DWAA (lossy) DWAB (lossy)

Điều khiển mức nén có mất dữ liệu (lossy) áp dụng lên hình ảnh, biểu diễn dưới dạng phần trăm. Nén lossy giảm kích thước file bằng cách loại bỏ một phần dữ liệu hình ảnh, có thể dẫn đến mất chi tiết.

  • 0%: Nén tối đa, tạo ra kích thước file nhỏ nhất nhưng mất chất lượng rõ rệt nhất.

  • 100%: Không nén, giữ nguyên toàn bộ chất lượng hình ảnh với cái giá là kích thước file lớn hơn.

Interleave

Dùng kiểu lưu trữ xen kẽ (interleaved) kiểu cũ cho các view, layer và pass để tương thích với các ứng dụng không hỗ trợ file OpenEXR multi-part hiệu quả hơn.

Preview

Khi render animation (hoặc các frame đơn qua dòng lệnh), lưu một bản sao JPEG của hình ảnh, để xem trước nhanh.

Radiance HDR¶

Radiance là một bộ công cụ mô phỏng chiếu sáng. Vì Radiance từng có định dạng hình ảnh HDR đầu tiên (và trong thời gian dài là duy nhất), định dạng này được nhiều gói phần mềm khác hỗ trợ.

File .hdr Radiance vẫn lưu màu ở 8 bit trên mỗi thành phần, nhưng có thêm một giá trị số mũ 8-bit (dùng chung), đưa tổng lên 32 bit trên mỗi điểm ảnh.

Metadata¶

Metadata là thông tin bổ sung được lưu bên trong file hình ảnh, mô tả hình ảnh được tạo ra như thế nào hoặc nên được diễn giải ra sao.

Blender có thể ghi metadata vào các định dạng hình ảnh được hỗ trợ khi được bật trong Output Properties.

Hạn chế¶

Không phải mọi định dạng đều hỗ trợ metadata, và một số có thể chỉ hỗ trợ một tập hợp trường hạn chế.

Khi dùng các định dạng không hỗ trợ metadata, thông tin render không được giữ lại trong file đã lưu.

Orientation Metadata¶

Metadata hướng (orientation) EXIF (thường thấy trong hình ảnh JPEG) bị bỏ qua khi tải hình ảnh vào Blender. Hình ảnh được hiển thị bằng dữ liệu điểm ảnh được lưu của chúng, không tự động xoay.

Nếu một hình ảnh bị xoay không đúng, nó có thể được điều chỉnh thủ công bằng Rotate 90° Clockwise.
