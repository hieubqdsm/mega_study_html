Pull Requests¶

Trang này mô tả các công cụ dùng cho đóng góp và review code.

Review là một biện pháp then chốt để đảm bảo các thay đổi có chất lượng tốt. Chúng giúp ngăn ngừa lỗi, sự thiếu nhất quán trong thiết kế, hoặc các vấn đề bảo trì tiềm ẩn. Việc để công việc của mình được review cũng thường giúp bạn luôn cẩn trọng.

Ghi chú

Những người viết đã được cấp quyền commit có thể commit vào repository chính mà không cần fork repository.

Xem Hướng dẫn commit nếu điều này áp dụng cho bạn.

Thiết lập một lần¶

Phần này giả định rằng bạn đã checkout repository tài liệu Blender trên máy tính của mình, theo hướng dẫn cài đặt.

Fork¶

  1. Truy cập repository của Blender và nhấp vào nút Fork.

  2. Xác nhận fork với các cài đặt mặc định.

  3. Bây giờ bạn cần thêm fork cá nhân của mình sebagai một remote trong repository git cục bộ. Nhấp SSH để xem URL chính xác, sau đó thêm nó như sau:

    git remote add me git@git.blender.org:<USERNAME>/blender-manual.git

Ghi chú

Để push lên repository fork, bạn cần một SSH key. Nếu bạn chưa có file ~/.ssh/id_rsa.pub, có một lệnh đơn giản để tạo các key như vậy, hoạt động trên Linux, macOS và trong Git Bash trên Windows:

ssh-keygen

Lệnh này sẽ tạo một private key id_rsa và một public key id_rsa.pub trong ~/.ssh. Private key tuyệt đối không được hiển thị hay gửi cho bất kỳ ai khác để tránh gây nguy hiểm cho bảo mật tài khoản của bạn, còn public key thì có thể chia sẻ an toàn.

Nội dung của ~/.ssh/id_rsa.pub có thể được sao chép và dán vào cài đặt tài khoản trên projects.blender.org, sau khi nhấp "Add Key". Đặt tên gì cho SSH key cũng được.

Workflow¶

Quy trình làm việc với pull request có thể được tìm thấy trong Tài liệu cho Nhà phát triển Blender.

Lưu ý, một số nội dung trong hướng dẫn trên tập trung vào repository chính của Blender, tuy nhiên quy trình làm việc là giống nhau cho mọi dự án Blender.

Hướng dẫn cho người review¶

  • Nội dung pull request nên có thể dùng làm thông điệp git commit (xem hướng dẫn để biết chi tiết).

  • Hãy nói rõ khi một số thay đổi cần được xử lý trước khi commit, mà không cần thêm một vòng review.

  • Nếu pull request không được chấp thuận, người tạo nó được kỳ vọng sẽ thực hiện một vòng chỉnh sửa nữa.

  • Nếu thay đổi cần được thống nhất trong design task trước, hãy tạm gác pull request bằng cách thêm tiền tố WIP: vào tiêu đề, cho biết tác giả cho rằng pull request chưa sẵn sàng để hợp nhất. Không cần review trừ khi tác giả chủ động yêu cầu.

  • Người viết được kỳ vọng phản hồi các pull request trong vòng 3 ngày làm việc.

  • Thêm các module/dự án liên quan vào nhãn.

  • Khuyến khích người viết mới tham gia review, đây là cách học tốt và quan trọng để dự án phát triển.

Mẹo¶

  • Để lấy file patch, thêm .patch vào cuối URL của pull request. Ví dụ:

    https://projects.blender.org/blender/blender-manual/pulls/104892.patch

  • Checkout một pull request vào một detached head (không để lại branch). Ví dụ:

    git fetch -q origin +refs/pull/104892/head: ; git checkout -qf FETCH_HEAD
