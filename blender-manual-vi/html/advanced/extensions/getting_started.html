Cách tạo Extension¶

Việc tạo một extension chỉ gồm vài bước:

  1. Mở thư mục chứa mã add-on hoặc file theme.

  2. Thêm một file blender_manifest.toml với đầy đủ các meta-data bắt buộc (name, maintainer, ...).

  3. Dùng công cụ dòng lệnh của Blender để build file .zip của extension.

Cách xuất bản lên Blender Extensions Platform:

  • Install from Disk để kiểm tra xem mọi thứ có hoạt động tốt không.

  • Tải lên file .zip (bước này yêu cầu Blender ID).

Extension sẽ được đưa vào hàng chờ xét duyệt, và được xuất bản sau khi đội kiểm duyệt phê duyệt.

Các file của extension¶

Một extension được chia sẻ dưới dạng file nén .zip chứa một file manifest cùng các file khác. Các file cần có tùy thuộc vào loại extension.

Extension dạng add-on¶

Add-on cần tối thiểu file manifest và một file __init__.py, trong khi các add-on phức tạp hơn có thể gồm nhiều file .py khác nhau hoặc kèm theo các wheel.

my_extension-0.0.1.zip
├─ __init__.py
├─ blender_manifest.toml
└─ (...)

Extension dạng theme¶

Một theme extension chỉ cần file manifest và file theme .xml.

my_extension-0.0.1.zip
├─ blender_manifest.toml
└─ theme.xml

Ghi chú

Extension có thể (tùy chọn) chứa tất cả các file bên trong một thư mục (bên trong file nén). Đây là hành vi phổ biến khi lưu repository dưới dạng ZIP từ các nền tảng quản lý phiên bản.

Manifest¶

Manifest là một file chứa toàn bộ meta-data cần thiết để extension được xử lý. Ví dụ này là một điểm khởi đầu tốt cho file blender_manifest.toml vốn phải nằm bên trong .zip.

schema_version = "1.0.0"

# Example of manifest file for a Blender extension
# Change the values according to your extension
id = "my_example_extension"
version = "1.0.0"
name = "My Example Extension"
tagline = "This is another extension"
maintainer = "Developer name"
# Supported types: "add-on", "theme"
type = "add-on"

# # Optional: link to documentation, support (public bug tracker), source files, etc.
# website = "https://extensions.blender.org/add-ons/my-example-package/"
# support = "https://projects.blender.org/user/my-example-package/issues"

# # Optional: tag list defined by Blender and server, see:
# # https://docs.blender.org/manual/en/latest/advanced/extensions/tags.html
# tags = ["Animation", "Sequencer"]

blender_version_min = "4.2.0"
# # Optional: Blender version that the extension does not support, earlier versions are supported.
# # This can be omitted and defined later on the extensions platform if an issue is found.
# blender_version_max = "5.1.0"

# License conforming to https://spdx.org/licenses/ (use "SPDX: prefix)
# https://docs.blender.org/manual/en/latest/advanced/extensions/licenses.html
license = [
  "SPDX:GPL-3.0-or-later",
]
# # Optional: required by some licenses.
# copyright = [
#   "2002-2024 Developer Name",
#   "1998 Company Name",
# ]

# # Optional: list of supported platforms. If omitted, the extension will be available in all operating systems.
# platforms = ["windows-x64", "macos-arm64", "linux-x64"]
# # Other supported platforms: "windows-arm64", "macos-x64"

# # Optional: bundle 3rd party Python modules.
# # https://docs.blender.org/manual/en/latest/advanced/extensions/python_wheels.html
# wheels = [
#   "./wheels/hexdump-3.3-py3-none-any.whl",
#   "./wheels/jsmin-3.0.1-py3-none-any.whl",
# ]

# # Optional: add-ons can list which resources they will require:
# # * files (for access of any filesystem operations)
# # * network (for internet access)
# # * clipboard (to read and/or write the system clipboard)
# # * camera (to capture photos and videos)
# # * microphone (to capture audio)
# #
# # If using network, remember to also check `bpy.app.online_access`
# # https://docs.blender.org/manual/en/latest/advanced/extensions/addons.html#internet-access
# #
# # For each permission it is important to also specify the reason why it is required.
# # Keep this a single short sentence without a period (.) at the end.
# # For longer explanations use the documentation or detail page.
#
# [permissions]
# network = "Need to sync motion-capture data to server"
# files = "Import/export FBX from/to disk"
# clipboard = "Copy and paste bone transforms"

# # Optional: advanced build settings.
# # https://docs.blender.org/manual/en/latest/advanced/command_line/extension_arguments.html#command-line-args-extension-build
# [build]
# # These are the default build excluded patterns.
# # You only need to edit them if you want different options.
# paths_exclude_pattern = [
#   "__pycache__/",
#   "/.git/",
#   "/*.zip",
# ]
Các giá trị bắt buộc:
blender_version_min:

Phiên bản Blender tối thiểu được hỗ trợ - dùng ít nhất 4.2.0.

id:

Định danh duy nhất của extension.

license:

Danh sách giấy phép, dùng định danh giấy phép SPDX.

maintainer:

Người duy trì extension.

name:

Tên đầy đủ của extension.

schema_version:

Phiên bản nội bộ của định dạng file - dùng 1.0.0.

tagline:

Mô tả ngắn gọn trong một dòng, tối đa 64 ký tự - không được kết thúc bằng dấu câu.

type:

"add-on", "theme".

version:

Phiên bản của extension - phải tuân theo semantic versioning.

Các giá trị tùy chọn:
blender_version_max:

Phiên bản Blender mà extension không hỗ trợ; các phiên bản sớm hơn vẫn được hỗ trợ.

website:

Trang web của extension.

copyright:

Một số giấy phép yêu cầu bản quyền; bản quyền phải ở dạng "Year Name" hoặc "Year-Year Name".

tags:

Danh sách các tag. Xem danh sách các tag khả dụng.

platforms:

Danh sách các nền tảng được hỗ trợ. Nếu bỏ qua, extension sẽ khả dụng trên mọi hệ điều hành. Các tùy chọn khả dụng là ["windows-x64", "windows-arm64", "macos-x64", "macos-arm64", "linux-x64"]

wheels:

Danh sách các đường dẫn file tương đối tới Python Wheels.

permissions:

Add-on có thể liệt kê những tài nguyên mà chúng cần. Các tùy chọn khả dụng là files, network, clipboard, camera, microphone. Mỗi quyền nên kèm theo một lời giải thích (một câu ngắn, tối đa 64 ký tự, không có dấu câu ở cuối).

Các giá trị tùy chọn cho "build":

Các giá trị này chỉ được dùng bởi lệnh con build.

paths:

Danh sách các đường dẫn file (tương đối so với file manifest) cần đưa vào khi build gói.

paths_exclude_pattern:

Danh sách các mẫu đường dẫn file cần loại bỏ khi build gói.

Cách khớp mẫu tương thích với gitignore.

Lưu ý rằng không thể đặt giá trị này khi paths cũng được khai báo.

Nếu bảng [build] không được khai báo, giá trị mặc định sau sẽ được dùng:

[build]
paths_exclude_pattern = [
  "__pycache__/",
  ".git",
  "*.zip",
]
Dành riêng:

Các giá trị này không được khai báo trong TOML và được dành riêng cho mục đích sử dụng nội bộ.

  • [build.generated]

Ghi chú

Tất cả các giá trị có trong file manifest phải được điền (tức là không được để trống, không được là chuỗi "", cũng không được là danh sách []).

Nếu không muốn đặt một trong các giá trị tùy chọn, chỉ cần bỏ hẳn nó khỏi manifest.

Dòng lệnh¶

Extension có thể được build, validate & cài đặt qua dòng lệnh.

Build¶

Để build gói được định nghĩa trong thư mục hiện tại, hãy dùng các lệnh sau:

blender --command extension build

Xem tài liệu về build.

Validate¶

Để validate manifest mà không cần build gói:

blender --command extension validate

Bạn cũng có thể validate một gói mà không cần giải nén nó trước.

blender --command extension validate add-on-package.zip

Xem tài liệu về validate.

Xuất bản¶

Để tự động hóa việc xuất bản các bản cập nhật trên Extension Platform, hãy xem tài liệu CI/CD.

Các trang extension của bên thứ ba¶

Nếu bạn muốn tự lưu trữ (host) các extension, hãy xem tài liệu Tạo một Repository Extension.
