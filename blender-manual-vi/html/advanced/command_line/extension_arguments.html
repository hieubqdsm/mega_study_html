Đối số dòng lệnh cho Extensions¶

Lệnh để quản lý các extension của Blender.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

lệnh con:

Quản lý Package
list:

Liệt kê tất cả package.

sync:

Đồng bộ với các repository từ xa.

update:

Nâng cấp mọi package đã lỗi thời.

install:

Cài đặt các package.

install-file:

Cài đặt package từ file.

remove:

Gỡ bỏ các package.

Quản lý Repository
repo-list:

Liệt kê các repository.

repo-add:

Thêm repository.

repo-remove:

Gỡ bỏ repository.

Tạo Extension
build:

Dựng một package.

validate:

Kiểm tra tính hợp lệ của một package.

server-generate:

Tạo một danh sách từ tất cả package.

Quản lý Package¶

Lệnh con: list¶

cách dùng:

blender --command extension list [-h] [-s]

Liệt kê các package từ tất cả repository đã bật.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

-s, --sync

Đồng bộ thư mục từ xa trước khi thực hiện thao tác.

Lệnh con: sync¶

cách dùng:

blender --command extension sync [-h]

Tải thông tin package cho các repository từ xa.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

Lệnh con: update¶

cách dùng:

blender --command extension update [-h] [-s]

Tải xuống và cập nhật mọi package đã lỗi thời.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

-s, --sync

Đồng bộ thư mục từ xa trước khi thực hiện thao tác.

Lệnh con: install¶

cách dùng:

blender --command extension install [-h] [-s] [-e] [--no-prefs]
                                    PACKAGES
đối số vị trí:
PACKAGES:

Các package để thao tác (phân tách bằng , không có khoảng trắng).

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

-s, --sync

Đồng bộ thư mục từ xa trước khi thực hiện thao tác.

-e, --enable

Bật extension sau khi cài đặt.

--no-prefs

Coi user-preferences là chỉ đọc, ngăn cập nhật cho những thao tác lẽ ra sẽ sửa đổi chúng. Nghĩa là chẳng hạn việc gỡ extension hay repository sẽ không cập nhật user-preferences.

Quản lý Repository¶

Lệnh con: repo-list¶

cách dùng:

blender --command extension repo-list [-h]

Liệt kê tất cả repository được lưu trong tùy chỉnh của Blender.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

Lệnh con: repo-add¶

cách dùng:

blender --command extension repo-add [-h] [--name NAME]
                                     [--directory DIRECTORY]
                                     [--url URL]
                                     [--access-token ACCESS_TOKEN]
                                     [--source SOURCE]
                                     [--cache BOOLEAN] [--clear-all]
                                     [--no-prefs]
                                     ID

Thêm một repository cục bộ hoặc từ xa mới.

đối số vị trí:
ID:

Định danh repository.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

--name NAME

Tên hiển thị trong giao diện (tùy chọn).

--directory DIRECTORY

Thư mục nơi repository lưu các file cục bộ (tùy chọn). Khi bỏ qua, một thư mục trong thư mục người dùng sẽ tự động được chọn.

--url URL

URL, dành cho repository từ xa (tùy chọn). Khi bỏ qua, repository được coi là "cục bộ" vì không kết nối với repository bên ngoài, khi đó package có thể được cài bằng file hoặc quản lý thủ công.

--access-token ACCESS_TOKEN

Token truy cập dùng cho các repository từ xa yêu cầu token.

--source SOURCE

Kiểu nguồn trong ('USER', 'SYSTEM'). Repository hệ thống được quản lý bên ngoài Blender và được coi là chỉ đọc.

--cache BOOLEAN

Dùng package cache (mặc định=1).

--clear-all

Xóa tất cả repository trước khi thêm, giúp đơn giản hóa việc thiết lập kiểm thử.

--no-prefs

Coi user-preferences là chỉ đọc, ngăn cập nhật cho những thao tác lẽ ra sẽ sửa đổi chúng. Nghĩa là chẳng hạn việc gỡ extension hay repository sẽ không cập nhật user-preferences.

Tạo Extension¶

Lệnh con: build¶

cách dùng:

blender --command extension build [-h] [--source-dir SOURCE_DIR]
                                  [--output-dir OUTPUT_DIR]
                                  [--output-filepath OUTPUT_FILEPATH]
                                  [--valid-tags VALID_TAGS_JSON]
                                  [--split-platforms] [--verbose]

Dựng một package trong thư mục hiện tại.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

--source-dir SOURCE_DIR

Thư mục nguồn của package chứa một manifest blender_manifest.toml.

Mặc định là thư mục hiện tại.

--output-dir OUTPUT_DIR

Thư mục đầu ra của package.

Mặc định là thư mục hiện tại.

--output-filepath OUTPUT_FILEPATH

Đường dẫn file đầu ra của package (nên có phần mở rộng .zip).

Mặc định là {id}-{version}.zip dùng các giá trị từ manifest.

--valid-tags VALID_TAGS_JSON

Tham chiếu một đường dẫn file chứa các danh sách tag hợp lệ.

Nếu bạn muốn tham chiếu các tag tùy chỉnh, có thể dùng một file .json. Nội dung phải là một dictionary của các danh sách, trong đó key khớp với kiểu extension.

Ví dụ:

{"add-ons": ["Example", "Another"], "theme": ["Other", "Tags"]}

Để tắt việc kiểm tra tag, hãy truyền một đường dẫn rỗng --valid-tags="".

--split-platforms

Dựng một package riêng cho từng nền tảng, thêm nền tảng làm hậu tố tên file (trước phần mở rộng).

Điều này có thể hữu ích để giảm dung lượng tải lên của các package đóng gói kèm các module riêng theo nền tảng có dung lượng lớn (các file *.whl).

--verbose

Bao gồm đầu ra chi tiết.

Lệnh con: validate¶

cách dùng:

blender --command extension validate [-h]
                                     [--valid-tags VALID_TAGS_JSON]
                                     [SOURCE_PATH]

Kiểm tra tính hợp lệ của siêu dữ liệu package trong thư mục hiện tại.

đối số vị trí:
SOURCE_PATH:

Đường dẫn nguồn của package (hoặc thư mục chứa các file package, hoặc kho nén package). Đường dẫn này phải chứa một manifest blender_manifest.toml.

Mặc định là thư mục hiện tại.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

--valid-tags VALID_TAGS_JSON

Tham chiếu một đường dẫn file chứa các danh sách tag hợp lệ.

Nếu bạn muốn tham chiếu các tag tùy chỉnh, có thể dùng một file .json. Nội dung phải là một dictionary của các danh sách, trong đó key khớp với kiểu extension.

Ví dụ:

{"add-ons": ["Example", "Another"], "theme": ["Other", "Tags"]}

Để tắt việc kiểm tra tag, hãy truyền một đường dẫn rỗng --valid-tags="".

Lệnh con: server-generate¶

cách dùng:

blender --command extension server-generate [-h] --repo-dir REPO_DIR
                                            [--repo-config REPO_CONFIG]
                                            [--html]
                                            [--html-template HTML_TEMPLATE_FILE]

Tạo một danh sách tất cả package được lưu trong một thư mục. Điều này có thể dùng để lưu trữ package, chỉ cần hosting file tĩnh.

tùy chọn:
-h, --help

hiển thị thông điệp trợ giúp này rồi thoát

--repo-dir REPO_DIR

Thư mục repository từ xa.

--repo-config REPO_CONFIG

Một cấu hình server tùy chọn để bao gồm thông tin không thể tự động phát hiện. Mặc định là blender_repo.toml (trong thư mục repository).

Điều này có thể được dùng để khai báo các extension bị chặn, ví dụ

schema_version = "1.0.0"

[[blocklist]]
id = "my_example_package"
reason = "Explanation for why this extension was blocked"
[[blocklist]]
id = "other_extension"
reason = "Another reason for why this is blocked"
--html

Tạo một file HTML (index.html) cùng với JSON của repository để hỗ trợ duyệt extension trực tuyến bằng hosting tĩnh.

--html-template HTML_TEMPLATE_FILE

Một đường dẫn file HTML tùy chọn để thay template HTML mặc định bằng template của riêng bạn.

Các khóa sau sẽ được thay bằng nội dung được tạo:

  • ${body} được thay bằng nội dung các extension.

  • ${date} được thay bằng ngày tạo.
